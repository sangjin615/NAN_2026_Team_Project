## 결론

이 ZIP은 **V6.1 기능·화면 계약의 기준 문서**로 사용하기에 충분히 구체적이다. 그러나 실행용 `index.html`이 의도적으로 없고, 70개 행동은 `spec-only`로 정의되어 있으며, 현재 `Runtime`에는 V6.1과 충돌하는 밸런스·플로우가 남아 있다. 따라서 현 상태를 “최종 게임 프로젝트”가 아니라 **구현 기준이 확정된 Visual Spec 패키지**로 분류해야 한다.

가장 먼저 할 일은 V6.1을 단일 기준 사양으로 승인하고, 기존 Runtime·밸런싱랩·제출 문서의 충돌 규칙을 V6.1로 마이그레이션하는 것이다.

## 잘된 점

1. 14개 씬의 기능, 행동, 데이터 소유권, 실패 표시 방식이 한 계약에 모였다.
2. 엔진은 수치·판정을 소유하고 API는 이름·설명·세계관 문구만 생성한다는 경계가 명확하다.
3. 현재 날짜+2일 생성 버퍼와 고정 템플릿 폴백 정책이 명시됐다.
4. 저장 슬롯의 `current/backup/temp` 원자 저장 및 경매 중 저장 금지 정책이 구체적이다.
5. 12일 본편과 최종 유물 경매, 영구 전시관의 관계가 정리됐다.
6. `actionRef`, `dataRefs`, UI 상태, 씬 전이가 모두 내부 계약에 연결돼 있다.
7. 제거할 레거시 규칙을 명시해 구현 중 옛 규칙이 다시 섞일 가능성을 줄였다.

## 에셋·VSL에서 추가로 필요한 것

### 실제 사운드 패키지 연결

`soundContract`는 `sound/sound.json`과 `assets/runtime/audio/sound-runtime.js`를 가리키지만 ZIP에는 두 파일과 음원 파일이 없다. 22종의 고유 `soundCue`가 42곳에서 참조되므로 다음 중 하나가 필요하다.

- 최종 ZIP에 `sound/sound.json`, runtime 매핑, BGM/SFX를 포함한다.
- 또는 이 ZIP이 명세 전용임을 유지하고, 사운드 저장소/패키지의 정확한 버전과 체크섬을 README에 외부 의존성으로 명시한다.

### 순수 배경이 없는 씬

다음 씬은 참조 목업만 있고 UI가 제거된 순수 배경이 없다.

- `scene-city`
- `scene-office`
- `scene-final`
- `scene-result`
- `scene-museum`

특히 `scene-office`는 상태값도 `mockup-available-pure-background-missing`으로 명시돼 있다. 구현 전에 배경을 분리하거나, 목업 전체를 배경으로 사용할 것인지 확정해야 한다.

### 미완성 표시 8곳

- 거래소 계열 시세판
- 결산 장부와 6계열 시세
- 결과 화면의 다음 여정
- 전시관 상단 상태·상세·영구 효과

이 항목은 기능 명세는 있으나 화면/데이터 연결이 `partial`이다. A 우선순위 구현에 포함해야 한다.

### 편집 실행 편의

VSL 도구 HTML은 포함됐지만 루트 실행기가 없다. 팀원이 ZIP을 풀고 바로 편집하게 하려면 기존 패키지처럼 레이아웃/사운드 실행 HTML을 루트에 포함하거나 README에 정확한 실행·불러오기 순서를 추가하는 편이 좋다.

## 문서에서 정리할 부분

1. `implemented` 표시는 주로 핀·레이아웃 주석의 배치 상태를 의미하고 실제 행동 구현은 `spec-only`다. 심사자 오해를 막기 위해 `layout-mapped` 같은 명칭으로 바꾸거나 README에 정의를 추가한다.
2. `CHANGELOG-V6-TO-V6.1.md`는 삭제된 씬 이미지를 ZIP에 보존했다고 쓰지만, `FINAL-CLEANUP-REPORT.md`는 삭제된 씬 폴더를 제거했다고 쓴다. 실제 ZIP에는 `scene-ending` 폴더가 없으므로 CHANGELOG 문장을 현재 상태에 맞춰 수정한다.
3. `IMPLEMENTATION-CHECKLIST.md`의 검증 항목은 모두 미체크지만 내부 참조 검사는 이미 통과했다. 자동 검증 항목과 실제 게임 동작 검증 항목을 나눠 표시한다.
4. 자체 검증 보고서에 사운드 외부 의존성과 Runtime 사양 충돌은 포함되지 않았다. 이번 검토 내용을 후속 검증 섹션에 추가한다.

## 완료 판정

다음 조건을 모두 만족해야 V6.1 구현 완료로 부를 수 있다.

1. 70개 action의 `spec-only`가 실제 runtime binding과 테스트로 전환된다.
2. 모든 A 우선순위 체크리스트가 실제 브라우저에서 통과한다.
3. V6.1 값으로 900시드 측정을 다시 실행해 일정·도달·실패 분포를 기록한다.

6. 사운드 의존성이 ZIP 내부 또는 명시된 외부 패키지에서 재현된다.
