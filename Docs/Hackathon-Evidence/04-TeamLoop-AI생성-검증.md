# Team Loop·스킬·하네스 AI 생성 검증

## 목적

외부 API를 바로 붙이기 전에 로컬 모델로 두 단계 생성 구조와 실패 처리 방식을 검증했다.

1. 런 시작 시 12일 시장 흐름·세트·서사 골격 생성
2. 매일 8 LOT의 설명·루머·세트 힌트·NPC 반응 생성
3. 플레이 중 현재 날짜보다 2일 앞까지 버퍼 유지
4. 실패 시 재시도하고, 계속 실패하면 폴백으로 게임 진행

엔진은 기준가·실제 가치·수치 규칙을 소유하고 AI는 표시 이름·설명·세트 관계·서사 문장을 소유한다.

## 실제 로컬 모델 결과

모델: Ollama `qwen3:14b`

| 생성 단계 | 시간 | 결과 |
|---|---:|---|
| 런 시작 골격 | 28.274초 | 계약 통과 |
| 1일차 최초 생성 | 23.797초 | LOT ID 변경으로 실패 |
| 강화 프롬프트 재생성 | 19.511초 | 계약 통과 |

첫 실패를 성공으로 숨기지 않았다. 모델이 엔진 ID를 바꾼 문제를 검증기가 차단했고, 정확한 ID 목록과 자동 교정 규칙을 추가해 통과시켰다.

## 장문 프롬프트와 스킬/하네스 비교

| 항목 | 장문 | 스킬/하네스 | 해석 |
|---|---:|---:|---|
| 입력 문자 | 4,710 | 1,918 | 59.3% 감소 |
| 최초 비교 입력 토큰 | 2,520 | 1,549 | 38.5% 감소 |
| 엄격 계약 통과 | 0/2 | 3/3 | 소표본 개선 |
| 관측 시간 | 25.778~48.400초 | 26.139~59.620초 | 속도 개선 입증 안 됨 |

가장 효율이 좋았던 요소는 모델 자체가 아니라 **짧은 계약 + 독립 검증기 + 실패 시 재시도/폴백** 조합이다. 입력은 짧아지고 구조 준수율은 좋아졌지만 로컬 추론 시간은 출력 길이와 재시도의 영향을 받아 더 빨라졌다고 말할 수 없다.

## Team Loop에서 검증한 범위

- 하네스 사전 시험 4/4 통과
- 시스템 검증 4/4 통과
- 프로젝트 통합 자동 테스트 8/8 통과
- 범위 위반 0건, 숫자 소유권 위반 0건
- Windows `npm.cmd` 실행 및 reviewer PID 전달 문제를 발견하고 수정

Team Loop 라이프사이클 전체가 최종 `DONE`까지 완료됐다는 주장과, 생성·스키마·게임 테스트가 통과했다는 주장은 구분해야 한다. 현재 강하게 쓸 수 있는 것은 후자다.

## API 도입 판단

현재 구조는 API 공급자를 교체할 수 있도록 계약과 런타임을 분리했다. 다음 단계에서는 동일 요청 세트를 외부 API에 보내 아래만 추가 측정하면 된다.

- 첫 시도 계약 통과율
- 재시도 포함 최종 성공률
- P50/P95 지연 시간
- 하루 8 LOT 생성 비용
- 폴백 발생률
- 사람의 문장 수정 비율
