# 독립 실행본은 파일 하나가 아니다

`build:standalone` 이 만드는 `미지의_경매장_서버없이_실행.html` 은 **서버가 필요
없을 뿐, 파일 하나로 도는 것이 아니다.** 이 문서는 그 사실과 실측만 남긴다.
줄이는 작업은 하지 않았다 — 게임 내용이 아직 바뀔 수 있어서 지금 하면 두 번
하게 된다 (2026-08-08 판단).

## 무엇이 박히고 무엇이 안 박히나

| | |
|---|---|
| HTML 크기 | 0.40 MB |
| `data:` URI | **0개** |
| 상대경로 `./assets/` 참조 | **211개** |

JS·CSS·`catalog.json`·`api-config.json` 은 인라인된다. **이미지와 오디오는 안
된다.** `tools/build-standalone.mjs` 는 바이너리를 박도록 만들어진 적이 없다.

**그래서 HTML 만 넘기면 배경·스프라이트·UI 가 전부 깨진다.** 게임은 뜨지만
그림이 없다. `assets/` 폴더를 옆에 함께 두어야 한다.

## 무게 (2026-08-08 실측)

| 폴더 | 크기 | HTML 참조 |
|---|---|---|
| `assets/audio` | 78.6 MB | 24건 |
| `assets/ui` | 44.8 MB | 164건 |
| `assets/scene-backgrounds` | 36.6 MB | 18건 |
| `assets/ui-mockups` | 25.4 MB | **0건** |
| `assets/relics` | 11.6 MB | 4건 |
| `assets/items` | 1.4 MB | 3건 |
| **합계** | **198.3 MB** (554 파일) | |

형식으로 보면 **PNG 354개 94.1 MB, WAV 111개 78.6 MB** 가 거의 전부다. BGM
루프 하나가 6.1 MB 짜리 무압축 WAV 다.

**`ui-mockups` 는 참조가 0건이다.** 디자인 참고물이라 제출본에서 빼도 된다.
빼면 173 MB.

## zip 은 답이 아니다 (실측)

| 표본 | 원본 | zip | |
|---|---|---|---|
| WAV 5개 | 30.3 MB | 26.4 MB | 원본의 87% |
| PNG 20개 | 40.6 MB | 40.4 MB | 원본의 **100%** |

PNG 는 내부가 이미 deflate 라 zip 이 전혀 안 먹는다. 통째로 묶어도 160 MB
언저리다. **zip 은 담는 그릇이지 줄이는 수단이 아니다.**

## 진짜 단일 파일을 원한다면

base64 는 용량을 **33% 늘린다.** 지금 상태로 인라인하면 230 MB 짜리 HTML 이
나온다. 브라우저가 열기는 하겠지만 파싱·디코딩만으로 한참 걸린다. **크기를
먼저 줄이지 않으면 의미가 없다.**

순서는 이렇다.

1. `ui-mockups` 삭제 — 참조 0건, 25.4 MB
2. **WAV → OGG/Opus** — 무압축 78.6 MB 가 여기 있다. 가장 큰 몫이다
3. **PNG → WebP** — 94.1 MB
4. `build-standalone.mjs` 에 바이너리 인라인 기능 추가 — 참조 211개

2~3번이 잘 되면 원본이 30~40 MB 대로 내려가고 인라인 후 40~55 MB 가 된다.
**다만 이 숫자는 추정이다** — 이 컴퓨터에 ffmpeg·ImageMagick·cwebp·sharp 가
하나도 없어서 변환을 실측하지 못했다. 프로젝트 의존성은 `esbuild` 뿐이다.

## 권하는 것

공모전이 단일 파일을 요구하지 않는다면 **폴더째 zip 으로 내는 것이 정상이고
심사위원도 그것을 예상한다.** 단일 파일을 위해 빌드 파이프라인을 새로 만들
값어치는 낮다.

**다만 1번과 2번은 어느 경로로 가든 해두는 편이 낫다.** 25 MB 는 그냥 낭비이고
무압축 WAV 78 MB 는 어떤 배포 형태에서도 부담이다. 둘만 해도 198 MB 에서 100 MB
아래로 내려간다.

**정하기 전에 확인할 것 — 제출 규격에 파일 형태나 용량 제한이 있는가.** 그것이
정해지면 위 선택은 자동으로 결정된다.
