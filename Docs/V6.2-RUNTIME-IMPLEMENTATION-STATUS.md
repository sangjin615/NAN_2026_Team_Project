# V6.2 Runtime 구현 현황

기준일: 2026-08-03  
목표: V6.1의 화면 흐름과 현재 Runtime의 검증 수치를 결합한 4일 내 해커톤 시연본

## 지금 실행되는 범위

- 12일 × 하루 8 LOT(총 96개) 고정 스케줄
- 3개 저장 슬롯과 current/backup/temp 기반 복구 저장
- 도시 허브에서 의뢰소, 거래소, 상회, 조합, 박물관, 경매장 이동
- 이미지 배경 및 PNG/9-slice UI 프레임
- 직접 아이템 제출 방식 의뢰와 경매 기회 3회 기한
- 상회 4단계, 확장 비용 7,500/12,000/17,500G, 창고 3/4/5/6칸
- 상회 2단계 대출 해금, 담보가 35%, 2일 만기, 만기 190%, 중도상환 100%
- 조합에서 담보 물품 직접 선택 및 대출액·만기 상환액 사전 확인
- 의뢰소 정밀 감정과 거래소 판매 기능 분리
- 유물 전시관 9칸 수집 현황, 획득 유물 이미지·효과 상세 패널
- 일반·유물 경매의 15초 행동 제한과 유물 경매 경쟁자 3명
- V6.4 사운드 프로그램의 장면 BGM과 핵심 행동 SFX 연결
- 현재일 + 2일 생성 버퍼와 API 실패 시 템플릿 폴백
- VSL 씬/액션/데이터 경로 계약을 Runtime DOM에 연결

## 검증 결과

- 자동 테스트: 12/12 통과
- 생성 스케줄: 900시드, 86,400 LOT, 무효 스케줄 0
- 브라우저: VSL 계약 로드 및 타이틀 액션 바인딩 확인

주의: 900시드 측정은 **LOT 생성 구조와 등급 분포 검증**이다. 변경된 대출·확장·의뢰 수치가 플레이 경제에 미치는 효과를 시뮬레이션한 결과는 아직 아니다. 해커톤 문서에서는 두 결과를 합쳐 표현하지 않는다.

## VSL과 Runtime의 역할

| 영역 | 기준 파일 | 역할 |
|---|---|---|
| 화면 좌표·크기·이미지 | VSL layout JSON | 사람이 수정하는 시각 사양 원본 |
| 씬·액션·데이터 대응 | `Runtime/contracts/vsl-map.template.json` | VSL ID와 실행 코드 연결 |
| 게임 수치 | `Runtime/contracts/v6.2-runtime-balance.json` | 발표 및 구현 기준 계약 |
| 실제 계산·저장 | `Runtime/src` | 브라우저 실행 로직 |

## 다음 우선순위

1. 모든 VSL 70개 액션과 107개 데이터 경로의 연결 범위를 최종 VSL 결과물 기준으로 재검사한다.
2. 밸런싱랩으로 경제 시뮬레이션을 수행해 성공률, 평균 현금, 확장 실패일, 대출 이용률을 측정한다.
3. 타이틀곡 `Blue Harbor Ledger`의 공개·재배포 권리를 제출 전에 확인한다.

## 사용자가 제공하면 바로 교체 가능한 것

- VSL 이후 수정본이 생기면 갱신된 layout JSON
- 화면별 확정 PNG 및 9-slice 여백값
- BGM/SFX 실제 파일과 이벤트 이름
- 의뢰 문구 및 API 출력 JSON의 최종 예시

현재 구조는 위 자료가 비어 있어도 폴백으로 실행되며, 자료가 도착하면 계약 파일과 에셋만 교체하도록 분리되어 있다.
