# NHN 해커톤 효과 측정 실행 문서

## 책임

측정 설계, 코드·Git·에셋·테스트·시뮬레이션 수집, 비교표 작성과 제출용 문장 작성은 Codex가 담당한다. 사용자는 자동으로 확인할 수 없는 사실만 답한다.

## Codex가 자동으로 수집하는 값

- 최근 8일 커밋·기여자·변경 이력
- 런타임 파일·코드·에셋·테스트 수
- 900시드 생성 유효성 및 등급 분포
- 플레이 로그의 완주, 낙찰, 의뢰, 대출, 실패 원인
- API 성공·실패·폴백·지연 시간(실제 API 연결 후)
- VSL 씬·요소 매핑 수와 재사용 수(VSL ZIP 수령 후)

실행 명령은 `Runtime`에서 `npm run measure`이다. 결과는 다음 파일에 누적한다.

- `Runtime/reports/generation-900-seeds.json`
- `Runtime/reports/project-evidence-current.json`
- 플레이어별 `unknown-auction-<seed>-day<day>.json`

## 사용자에게 필요한 최소 입력

아래 세 값만 자동 수집할 수 없다. 실제 수치가 생겼을 때 Codex가 한 번에 질문한다.

1. 기존 방식으로 비슷한 화면 하나를 만드는 데 걸린 시간
2. VSL ZIP을 처음 적용하는 데 실제로 걸린 시간
3. 팀 또는 외부 플레이테스터의 짧은 평가

사용자는 별도의 측정표를 관리할 필요가 없다. 작업 시작·완료 메시지를 대화에 남기면 Codex가 시간 근거로 정리한다.

## 평가 질문

VSL과 생성 템플릿이 8일 동안 미지의 경매장 프로젝트의 제작 속도, 실제 플레이 가능 범위, 반복 검증 가능성을 얼마나 개선했는가?

| 영역 | 지표 | 책임 |
|---|---|---|
| 제작 속도 | 씬 구현·수정 시간 | Codex 정리, 사용자 시각 확인 |
| 자동화 | 자동 매핑 요소/수동 수정 수 | Codex |
| 콘텐츠 | API 성공률·폴백률·지연 | Codex |
| 게임 완성도 | 완주율·진행 불가·오류 | Codex |
| 밸런스 | 목표 달성률·마감 실패·생존 중앙값 | Codex |
| 재사용성 | 재사용 씬·모듈·스키마 수 | Codex |

## 단계별 비교

- 0단계: 문서·목업·밸런싱랩만 존재
- 1단계: VSL ZIP과 밸런싱 문서
- 2단계: 생성 API가 채운 템플릿
- 3단계: 같은 프로젝트에서 시드별 변형 검증

동일 시드와 동일 측정 정책을 유지한다. 성공 사례만 선택하지 않는다.

## 현재 확보된 증거

- 12일 × 8 LOT 구조와 240개 아이템 스프라이트
- 모듈형 런타임, 장소 이동, 경제·경매·메타 시스템
- 자동 테스트 8개
- 900시드 86,400 LOT 생성, 잘못된 일정 0건
- 생성 API와 VSL 매핑 계약
- JSON 플레이 행동 기록

실제 API와 VSL 결과물이 도착하면 이 문서를 기준으로 적용 전후 수치를 자동 갱신한다.
