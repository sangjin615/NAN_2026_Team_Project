# 003 구매봇(L2) — 구현 표면 추림

- 상태: 브레인스토밍 착수 문서 (결정 아님). 002 체인의 L2 개방 확정을 전제로, "구현해야 하는 알고리즘"만 추린 것.
- 근거: `002-bot-v2.value-model.md` §2(스코프 사다리)·§5(입력 인벤토리), `002-bot-v2.impl-handoff.md` §4(스코프 플래그)·§6(미결), summary 타 트랙 전달 사항.
- 원칙 상속: 스코프 기준 ③ — **구매봇은 새 의사결정 루프가 아니다.** 기존 봇 상태의 재사용만 허용.

---

## 0. 위상 정의 (2026-07-24 논의 — 결재 대상)

**구매봇은 메인 클리어 요소가 아니다.** 메인 클리어는 경로 사다리 + 판매층 마찰(E05)의 비인격 경제 시스템이 담당하고, 구매봇은 그 위에 얹히는 **예외적 고가 제안층**이다 (동기·사정이 맞을 때 가끔 시세를 넘는 제안).

- 근거: ① 메인 출구를 봇에 걸면 제안가 누설(§2-7)이 예외에서 구조적 상수로 승격 ② 메인 출구 봇은 협상·수요 같은 새 의사결정 루프를 요구하게 됨 — 스코프 기준 ③ 위반, L4 경사로 ③ 무지성 매수 억제는 마찰의 몫이라는 시뮬 판정.
- **컷 테스트 (필수 통과)**: "구매봇을 통째로 빼도 런이 클리어 가능한가" = 예스 유지. 노가 되는 순간 위상 재검토.
- 거래소 목업(2026-07-24 공유)이 이 위상과 일치: 기본 출구 = "AI 감정사 즉시 매입"(비인격 시세) + 세트 처분. 구매봇 자리는 조건부 "특별 제안" 슬롯 — 없어도 화면 성립.

### 0.1 목업에서 추출한 밸런스 노브 (경제 트랙 전달)

즉시 매입 계수(예상가 대비) / 세트 배수 범위(목업 2.5~5배) / 보관 공간 상한(목업 20) / 장날 주기 / 시장 수요 단계(시세 트렌드 노출) / 감정사 평가 보정(목업 +15%). 전부 balance 데이터로 관리할 것. 표현 스케일(목업 8,000G대)과 엔진 스케일(10~60G)의 환산은 별도 1회 정리.

## 1. 이미 설계 확정 — 그대로 구현하면 되는 것

| 항목 | 확정 내용 | 출처 |
|---|---|---|
| 지갑 비연동 | 유저가 팔아도 경매 지갑 불변. 구매는 오프스크린 자금 | 6.1 확정 |
| 제안가 앵커 | est_bot × 동기 계수 (누설 차단 유지) | value-model §2 |
| 취향 | 동기 태그·favCat·사정축 매칭 — 전부 기존 입력 재사용, 신규 입력 0 | value-model §5 |
| 구매 한도 임시값 | 세션당 1건, 제안가 ≤ est_bot × 1.2 | impl-handoff §6 |
| L1 진열 | D 낙찰품 며칠 뒤 거래소 진열, 진열가 = 지불가×(1+마진), 계열 온도 반영 | impl-handoff §4 |

## 2. 구현해야 하는 알고리즘 표면 (전부)

엔진 함수 6개 + 하네스 3종. 이게 전부다.

1. **관심 판정** `botInterestInListing(npc, listing)` — 동기 태그·favCat·사정 매칭 → 관심 점수. **임계값 미달 = 무반응** (쓰레기 처분 착취 차단 1차 방어).
2. **제안가 산식** `botOfferPrice(npc, listing)` — est_bot × 동기 계수, 사정 매칭 시 사정축 반영, 캡 ≤ est_bot×1.2(임시). ※ §5 누설 주의 참조.
3. **한도 관리** — npc별 세션 구매 카운터 (임시: 1건). 상태 필드 1개.
4. **등장 스케줄** `pickExchangeBuyers(session)` — 그 세션 거래소에 구매자로 서는 봇 선정. ※ §4 설계 미결.
5. **사정 충족 연동** — 거래소 구매가 sajeong.satisfied를 올리는가. ※ §4 설계 미결 (아크·소모전 규칙과 얽힘).
6. **L1 진열 처리** — D 낙찰 시 진열 예약(day+n), 진열 목록 생성, 계열 온도 갱신. 의사결정 없음, 순수 상태 처리.

**검증 하네스 신규 3종** (002 하네스에 §5.7~5.9로 증설):

7. **제안가 누설 검정** — 봇 제안가의 공시 통제 잔차 ⟂ 실가치. **경매(3좌석 종합)보다 직접적인 누설 통로**: 제안은 1:1이고 반복 관찰 가능. 경매 캡보다 엄격한 상한 필요할 수 있음.
8. **착취 차단 검정** — 쓰레기(저가치) 대량 등록 시뮬 → 봇 매입 총액이 상한 이하.
9. **지갑 비연동 회귀** — 거래소 거래 후 경매 지갑 불변.

## 3. 설계를 미리 할 수 있는 것 (구현 전 결정 필요 — 브레인스토밍 대상)

1. **등장 규칙**: 세션 좌석 3(단골2+뜨내기1)과 연동? 별도 추첨? 단골만? — 아크 가독성엔 단골 위주가 유리.
2. **사정 충족 경로**: 유저가 사정 대상 물건을 낙찰받아 거래소에 올리면 그 봇이 사서 충족되는가? 열리면 "사정 되팔이"라는 새 전략(소모전 §4의 거래소 판)이 생김 — 재미인가 구멍인가 판정 필요.
3. **관심 임계값 수치**와 착취 차단선 (열린 질문 기존 항목).
4. **제안 상호작용 형태**: 봇이 먼저 제안하는가, 유저 등록에 반응하는가, 제안 수명·거절 후 재제안 — §15 MVP 거래소 UI와 호환 확인 필요 (A트랙 협의).
5. **경제 트랙 이관분**: L1 진열품과 유저 매물의 경쟁 여부 / 판매층 마찰(수수료·미판매 위험·경로 사다리)과 제안가의 결합 — **E05와 공동 설계** (sim 관찰 7: 마찰은 무지성 매수 억제의 핵심이므로 구매봇이 마찰을 우회하는 설계가 되면 안 됨).

## 4. 경계 — 하지 말 것

- 유저 경로 훔쳐보기 금지 (경로 커버리지 원칙의 치팅 금지 조항 — 읽는 것은 공개 정보와 자기 사정뿐)
- 구매봇 전용 가치 재추정 금지 (est_bot 재사용 — 뇌는 커지지 않는다)
- 지갑 연동 금지 (6.1 재검토 조건 발동 전까지)

## 5. 순서 제안

②(사정 충족 경로)와 ①(등장 규칙)만 브레인스토밍으로 정하면 §2의 1~6은 즉시 구현 가능. 하네스 7~9는 002 하네스 증설이라 반나절. E05(마찰)와의 결합(③⑤)은 병행 설계 — 구매봇 구현을 막지 않음 (계수 자리만 뚫어두면 됨).
