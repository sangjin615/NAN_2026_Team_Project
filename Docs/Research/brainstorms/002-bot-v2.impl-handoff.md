## 1. 데이터 구조

### 1.1 경쟁자 NPC (런 시작 시 엔진이 생성 → AI가 표현 생성)

```js
CompetitorNPC {
  id, seedRef,
  root: 'A'|'B'|'C'|'D',
  branch: 'A1'..'D3',
  identity: 'regular'|'drifter'|'nemesis'|'royal',   // 단골|뜨내기|숙적|왕립(최종전 전용)
  wallet: number,               // 런 지속 (뜨내기는 세션 스코프)
  noiseBand: 0.30,              // 숙적만 0.15 (공표 조건부 — 승인 필요 항목)
  favCat: catId, linkId: id,    // 관심 계열 / B2용 링크
  sajeong: [ {                  // 사정축 (0~3개)
    type: 'item'|'cat'|'link'|'deadline',
    key: itemId|catId|linkId,
    amount: number,             // ← 실가치 비참조 독립 추첨 (생성 시점 금지)
    deadline: day|null,
    satisfied: false
  } ],
  holdings: {catId: count},
  pendingRefunds: [{day, amount}],   // D 전용 오프스크린 환금
  expr: { name, motiveArchetypeId, motiveText, behindText }  // AI 생성 (판정 비참조)
}
```

### 1.2 plan 반환 스키마 (computeBotPlan 확장)

```js
BotPlan {
  maxPay,                        // max(시장축, 사정축), 자금 캡 적용
  interest,                      // 기존 분리 유지 (004)
  jumpProb, jumpAmp,             // 브랜치별 (004 파라미터화 계승)
  policy: {                      // ★신규 — "plan은 정책을 고정한다" (승인 필요 항목)
    roundJumpAfter: n|null,      // n라운드 초과 시 점프 (Tier 1)
    ratioSteps: [{below: r, amp}], // 현재가/est 구간별 점프 폭 (Tier 1)
    duelBias: ±x|null,           // 1:1 잔존 시 지속 의지 보정 (Tier 1)
    leadBias: {target: 'player', delta}|null  // 숙적 전용 (Tier 2 유일 허용)
  }
}
```

step(botStep)은 **plan.policy의 실행만** 한다. step에서 읽을 수 있는 것: 현재가, 최소 인상폭, 라운드 수, 잔존 경쟁자 수, (숙적만) 현재 리드 식별. **금지: 가치 재추정, 유저 망설임 시간.**

## 2. 산식 (한곳 정리)

```
est_bot   = 실가치 × U(1−noise, 1+noise)          # 물건×봇 쌍마다 카탈로그 시점 고정
시장축     = branchFormula(est_bot, ctx) × uplift   # 표는 trait-tree-reference — sim.py market_axis()가 참조 구현
            캡: est_bot × 1.5
사정축     = 매칭되는 sajeong.amount (deadline 임박 D-2~D일 ×1.3, 경과 시 0)
            캡: amount 자체
maxPay    = min( max(시장축, 사정축) + 소진압력, 세션예산, 지갑 )

소진압력   : 세션예산 B = W × ρ × (1 + λ·day/N)     # ρ0.5 λ0.75
            여유 = B잔여 − 남은출품수 × 0.6·A_s
            여유>0 → maxPay += 여유/남은출품수 × k   # k 0.25
D 환금     : 낙찰 t일 후 지갑 += 지불가×(1+마진)×U(0.9,1.15)   # est 기반 근사 — 실가치 비참조 유지
왕립급     : 사정축 단독(유물), 캡 est×2.0, 소진압력 004 단판 원형, 지갑 = 유저 최종현금×U(0.6,1.4)
```

시뮬 권고 노브(임시): `floor(경매 시작가) = 0.5 × 공시중앙`, `uplift = 1.15`. 근거·경계는 sim-findings 관찰 7~8 (과도 상향 시 승자의 저주로 봇 과지불 1.2×V).

## 3. 런 수명주기 (구현 순서 그대로)

1. **런 시작**: 엔진이 캐스트 생성(단골 3~4, 뿌리 중복 회피) → 사정 배정(단골: 지정형+조건형 / B뿌리 필수, 기한형 1인) → **그 후** AI가 expr 생성(공개 정보만 인용 — 하네스 검증).
2. **세션 시작**: 좌석 3 = 단골 2 + 뜨내기 1(즉석 생성), 서로 다른 뿌리. 세션예산 산출. 환금 도착 처리.
3. **물건별 plan**: 카탈로그 순회하며 BotPlan 고정 (경매 중 불변).
4. **경매 step**: policy 실행만.
5. **낙찰 처리**: 지갑 차감, holdings 갱신, 사정 satisfied 판정(→ 이후 plan에서 해당 사정 제외 = 아크 전환), D면 환금 예약.
6. **런 종료**: 왕립급은 별도 단판 (기존 004 경로 재사용 가능성 큼).

## 4. 스코프 플래그 (구현 포함/제외)

| 항목 | 판정 |
|---|---|
| L1 흔적 (D 낙찰품 거래소 진열, 계열 온도 반영) | 포함 — 진열가 = 지불가×(1+마진) |
| L2 봇=구매자 (거래소 제안, est_bot×동기 계수, 구매 한도) | 포함 — **지갑 비연동 확정** (구매는 오프스크린 자금) |
| L3 소문 훅 | 제외, 인터페이스 자리만 (봇 상태 read-only getter) |
| L4 경쟁 상회 시뮬 | **기각 확정 — 구현 금지** |
| 숙적 | 상회 단계 2부터 (MVP 후반) — identity 필드만 먼저 |
| Tier 3 (herding·망설임 읽기) | 구현 금지 |
| 유저 보관품 봇 공개 | 확정 — plan ctx에 유저 holdings 포함 (A3·B3 견제 입력) |

## 5. 검증 하네스 체크리스트 (테스트 코드로)

1. **생성 시점**: 사정 amount와 대상 물건 실가치의 상관 = 0 (배치 검정), 동기 텍스트에 숨은 태그·실가치 문자열 부재.
2. **plan 불변성**: 경매 중 maxPay·policy 변경 없음 (시드 재현 회귀).
3. **누설 회귀**: 봇 3좌석 낙찰가의 공시 통제 잔차 상관 ≤ 0.3 (기준선: sim 0.26).
4. **소진**: 수집형 런 종료 지갑 ≤ 초기 20% 대역 (sim 5~8% 재현 확인).
5. **캡**: 시장축 ≤ est×1.5, 사정축 ≤ amount, 왕립 ≤ est×2.0.
6. 기존 엔진 회귀(40시드×3스타일) 시드 확대 — 뿌리 4택3 조합 반영.
