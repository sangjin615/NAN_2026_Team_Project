# 설계 결정 — 봇 성향 트리 재편 (뿌리 3 × 브랜치 3)

- 상태: 1차 설계 합의 (수치는 전부 밸런싱 대상 임시값)
- 배경: 플레이테스트에서 ① "가치 불문 매수" 전략이 지배적(점수식이 잔액 0점이라 종료 시점 돈은 무가치) ② 봇 다수가 시작 자금 200을 거의 그대로 들고 종료. 원인은 봇 maxPay가 전부 추정치 이하로 보수적이고 자금 소진 개념이 없기 때문. 점수식(§14) 변경 대신 봇 측 수정으로 대응하기로 함. 아울러 모놀리식 5성향(§10.1)은 사실상 "기준 가치평가 × 할인율 + 보너스 + 상한"의 변주이므로 축 기반 트리로 재편.

## 선택한 안

**뿌리 3종 × 브랜치 3종 = 9변종.** 시드 선택은 기존과 동일하게 "서로 다른 뿌리 3개"를 뽑는다. 뿌리는 가치평가 소스(행동에 가장 크게 드러나는 축)로 가르고, 브랜치는 코드로 확인된 5축(평가 소스 / 가치 수정자 / 자금 정책 / 관심 분리 / 입찰 행동)의 조합으로 변주한다. 자유 조합이 아닌 트리를 택한 이유: 추론 게임에서 "뿌리는 읽히되 변종은 확신 못 하는" 긴장감 유지.

### 뿌리 A — 자기 추정 신뢰형 (소스: botEstimates)
- A1 정석형: maxPay=est. 점프 없음. 현 valuator 직계.
- A2 저격형: est > TIER_MID인 물건만 est×1.1, 나머지 est×0.8. 저격 대상에 interest↑(첫 행동 선점), 점프 확률·폭 큼.
- A3 관리형: 현 banker의 예산 상한 유지 + 타인 잔액 열람 — 경쟁자 평균 잔액이 자기보다 낮으면 상한 해제(공통 소진 압력 k 증폭). 타인 보유 겹침 읽기: **견제**(상대 세트 진행 조각에 가산).

### 뿌리 B — 관계 추적형 (소스: est + 수정자 중심)
- B1 키워드형: 현 setTracker(highlightTerms 겹침 보너스) 유지.
- B2 링크형: 현 privateTrust(ownerLinkIds 보너스) 유지.
- B3 올인형: 겹침·링크 보너스 둘 다 크게. 소유 0개 동안 est×1.0 + interest 최대("첫 조각" 집착), 판 절반까지 못 잡으면 est×0.7로 급락. 타인 보유 겹침 읽기: **견제**.

### 뿌리 C — 시장·공개정보형 (소스: 티어·공개문장·시장 이력)
- C1 공개정보형: 현 publicFocus(TIER_MID + 공개문장×2) 유지.
- C2 추세형: 직전 3~4건의 (낙찰가 / TIER_MID) 비율 평균을 기준가에 곱함. 시장 이력(itemState) 읽기 — §10.3의 "이전 공개 시장 결과 약하게 반영" 조항 활용, 신규 구현 필요. 점프 확률도 시장 온도에 연동.
- C3 역발상형: 유찰·저가 낙찰 누적 시 기준가 상향. 재경매 계수 ×0.9를 유일하게 ×1.05로 반전. 타인 보유 겹침 읽기: **회피**(경합 예상 물건 감산).

### 공통 규칙
- **소진 압력(전 봇 공통)**: 여유 = 잔액 − 남은 경매 수×30. 양수면 maxPay += 여유/남은 수 × k(기본 k 0.2~0.3, 브랜치 계수로 증폭). 남은 수 감소에 따라 압력이 자연 가속.
- **상한 캡**: 소진 압력·견제 가산 후에도 maxPay ≤ est×1.5(티어 기반 봇은 티어 상단×1.5). 근거: 과입찰은 §14.3 동률에서 불리 + 봇이 바보로 보이면 안 됨.
- **타인 보유 읽기**: 대상 물건의 키워드·링크와 타 참가자(플레이어 포함) 보유물의 겹침. §10.2 공개 정보이므로 합법. plan 계산 시점 입력이므로 §10.3(경매 중 고정)과 무충돌. A3·B3 견제 / C3 회피에만 배정.
- **입찰 행동 파라미터화**: botStep의 점프 확률(0.22/0.12)·폭(+3/+8)을 plan으로 이동, 브랜치별 값.
- **interest ≠ maxPay 분리**: computeBotPlan 반환 스키마는 이미 분리돼 있음. A2·B3가 사용.
- **추정 노이즈**: 전 봇 ±30% 균일 유지(성향≠실력 원칙).
