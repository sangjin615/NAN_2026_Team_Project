# NAN 2026 제출 체크리스트

공식 공고 기준으로 아래 항목 중 하나라도 누락되면 심사 대상에서 제외될 수 있다.

## 1. 플레이 가능한 빌드 및 전체 소스

- [ ] 링크 클릭만으로 실행되는 웹 빌드 배포
- [ ] GitHub Pages 또는 동등한 공개 URL 확인
- [ ] 시크릿 모드/로그아웃 상태에서 접근 확인
- [x] 전체 소스 저장소 주소 확인: https://github.com/sangjin615/NAN_2026_Team_Project
- [x] 기존 팀 커밋 기록 존재 확인
- [x] README에 로컬 실행 방법 기재
- [ ] 유료 라이선스 없이 심사자가 플레이 가능한지 확인
- [ ] 비공개 저장소 공개 전환 또는 심사 계정 초대 — 2026-08-03 현재 PRIVATE
- [ ] PC `.exe` 제출에 의존하지 않기

## 2. 실제 플레이 영상

- [ ] 30~60초 분량
- [ ] 실제 게임 화면만 사용
- [ ] AI 합성 플레이 영상 사용 금지
- [ ] YouTube 공개 또는 일부 공개 업로드
- [ ] 시작 5초 안에 게임 정체성이 보이는지 확인
- [ ] 경매 → 판단 → 낙찰/결과 흐름 포함
- [ ] URL을 두 PDF에 모두 삽입

## 3. 게임 소개 및 설명 PDF

- [ ] 게임 제목과 한 줄 소개
- [ ] 목표·조작·종료 조건
- [ ] 실행 방법
- [ ] 웹 플레이 URL
- [ ] GitHub URL
- [ ] YouTube URL
- [ ] 대표 화면 2~4장
- [ ] 로컬 경로와 상태 표기 제거

초안 원고에는 제목, 한 줄 소개, 목표, 조작, 종료 조건, 로컬 실행법과 GitHub 주소까지 작성되어 있다. 공개 URL·YouTube·대표 화면·연락처를 넣은 뒤 체크한다.

## 4. AI 활용 기술 PDF

- [ ] AI를 사용한 이유
- [ ] 엔진과 AI의 역할 경계
- [ ] 런 시작/일일 2단계 생성 구조
- [ ] 주요 프롬프트와 지시 사항
- [ ] 사용 도구·모델·버전
- [ ] 실제 활용 내역
- [ ] 측정 결과와 한계
- [ ] 외부 에셋·오픈소스 출처 및 라이선스
- [ ] AI 생성 에셋 표시
- [ ] VSL/Team Loop는 게임 효과와 연결해 설명

초안 원고에는 역할 경계, 2단계 생성, 프롬프트 계약, 현재 측정치와 한계가 작성되어 있다. 최종 API·VSL 버전·에셋 라이선스만 팀 확인이 필수다.

## 5. 팀원 롤 기술서

- [ ] 2인 이상이면 PDF 제출
- [ ] 팀원별 이름과 역할
- [ ] 실제 구현 영역
- [ ] 기획·개발·아트·AI 활용 구분
- [ ] 협업·분업 방식
- [ ] 개인 참여라면 제출 생략 가능 여부 최종 확인

## 마감 전 우선순위

### P0 — 제출 불가를 막는 항목

1. 웹 빌드 완주 가능
2. 공개 플레이 URL
3. 전체 소스와 커밋 기록
4. 30~60초 실제 플레이 영상
5. 게임 설명 PDF
6. AI 기술 PDF와 출처 표

### P1 — 선발 가능성을 높이는 항목

1. VSL 최종 화면 적용
2. 서로 다른 시드의 콘텐츠 차이 시연
3. 생성 실패 시 폴백 시연
4. 실제 플레이테스트 3~5명
5. 최종 API 10회 성공률·지연시간 측정

### P2 — 시간 여유가 있을 때

1. Team Loop 내부 기술 상세 부록
2. 대규모 모델 비교
3. 추가 시각효과 변형
4. 장문의 개발 회고

- [ ] 영상 음량과 자막 확인
