# 미지의 경매장 — MVP 제품 명세

- 문서 상태: 초안
- 대상 버전: MVP
- 공식 언어: 한국어
- 공식 환경: 최신 데스크톱 Chrome
- 기준 화면: 권장 1920×1080, 최소 1366×768, 브라우저 확대 100%
- 문서 원칙: 이 문서의 수치와 규칙은 영구 불변값이 아니라 **현재 MVP 기준** 또는 **MVP 임시값**이다.

---

## 0. 문서 목적

이 문서는 불완전한 정보 아래에서 물건의 실제 가치와 숨은 관계를 추론하고, 전체 출품 목록을 바탕으로 제한된 자본을 배분하는 싱글플레이 경매 게임의 MVP 구현 기준을 정의한다.

이 문서는 다음을 구분한다.

- **현재 MVP 기준**: 이번 구현에서 따라야 하는 규칙과 범위
- **MVP 임시값**: 구현·밸런스 테스트를 위해 우선 정한 수치와 표현
- **후속 검토 항목**: 플레이테스트 또는 재설계 이후 결정할 내용

### 0.1 브레인스토밍 변경 통제

이 문서는 브레인스토밍의 기준 문서이며 탐색 실행 중 직접 수정하지 않는다. 아래 세 등급은 개별 문장의 강도보다 우선한다.

#### 불변 조건

- 싱글플레이 경매 게임이다.
- 최초 경매 물건은 12개이며 전체 카탈로그를 경매 전에 공개한다.
- 플레이어 1명과 알고리즘 경쟁자 3명이 제한된 자본으로 경쟁한다.
- 물건의 실제 가치와 실제 세트 구성은 게임 종료 전까지 숨긴다.
- 생성 모델은 표현 콘텐츠를 담당하고 알고리즘은 가치, 세트, 입찰, 점수와 재현성을 판정한다.
- 플레이 도중 생성 모델을 호출하지 않는다.
- 최종 결과는 플레이어가 자신의 판단을 복기할 수 있어야 한다.

#### 현재 설계 가설

다음은 구현 후보의 기준안이지 영구 불변 조건이 아니다. 브레인스토밍 후보는 변경할 수 있지만 변경 이유와 검증 방법을 명시해야 한다.

- 공개 호가식 경매와 15초 행동 제한
- 시작 자금 200과 실제 가치 10–60
- 최소 인상폭 2와 `+2/+5/+10` 조작
- 2개 부분 세트 보상 +10, 3개 완성 보상 +35
- 세트 물건 9개와 독립 물건 3개
- 유찰 물건의 1회 재경매
- 소유자 전용 정보
- 남은 자금을 점수에 포함하지 않는 공식
- 약 15분의 목표 플레이 시간

#### 탐색 가능 영역

- 가치 추론, 세트 투자, 자본 운용, 경쟁 압력의 우선순위
- 공개 호가와 비공개 동시 입찰을 포함한 경매 형식
- 정보 공개 단계와 정보량
- 부분 세트 보상과 단품 전략의 균형
- 봇이 만드는 경제적 압력의 방식
- 재경매, 시간 제한, 시작가와 인상폭
- 결과 화면의 판단 복기 방식
- 현재 설계 가설의 수치와 UX 세부사항

브레인스토밍 결과는 이 문서를 자동 변경하지 않는다. 사람이 선택한 결정 문서가 승인된 뒤 별도의 명세 변경 작업에서 반영한다.

## 1. 제품 정의

### 1.1 한 문장 정의

판타지 세계의 경매 카탈로그 12개를 미리 검토하고, 숨은 가치와 세트 관계를 추론해 제한된 자본을 배분하는 싱글플레이 공개 호가식 경매 게임.

### 1.2 핵심 플레이 감정

플레이어가 느껴야 하는 중심 감정은 다음과 같다.

1. 전체 물건을 보고 자금 배분 계획을 세운다.
2. 공개 단서와 경쟁자의 행동으로 가설을 수정한다.
3. 지금 물건에 더 투자할지, 후반 기회를 위해 포기할지 결정한다.
4. 최종 공개에서 자신의 판단이 실제 가치와 세트 관계에 얼마나 적중했는지 확인한다.

### 1.3 핵심 재미

#### 가치 판단

플레이어는 물건 설명, 반복되는 인물·사건·장소·상징, 공개된 추가 정보로 실제 가치를 추정한다.

#### 자본 운용

플레이어는 현재 물건 하나만 보는 것이 아니라, 앞으로 등장할 모든 물건과 자신의 목표 세트를 고려해 자금을 배분한다.

#### 가설 검증

플레이어는 물건 사이의 숨은 관계를 추론하고 실제 자본을 걸어 수집한다. 게임 종료 시 실제 가치와 세트 구성이 공개되어 판단을 검증한다.

#### 경쟁 압력

경쟁자는 추리 정답을 맞히는 대상이 아니라 가격과 기회비용을 만드는 경제적 압력이다. 플레이어는 경쟁자의 잔액, 보유 물건, 입찰 행동을 보고 전략을 조정한다.

## 2. 설계 원칙

### 2.1 판 내부 일관성, 판 사이 변화

각 게임은 다른 중심 사건, 세트, 물건, 가치 배치를 가질 수 있다. 다만 한 게임 안에서는 다음이 일관되어야 한다.

- 하나의 중심 사건 또는 시대
- 같은 세계관·지역권·역사적 맥락
- 세트 구성 원리
- 단서와 숨은 사실의 관계
- 물건 간 인물·사건·장소·기능 연결
- 경쟁자의 경제적 행동

플레이어가 외워야 하는 것은 고정 정답표가 아니라 현재 판의 규칙과 관계를 읽는 방법이다.

### 2.2 생성 모델은 표현하고, 알고리즘은 판정한다

생성 모델은 다음을 담당한다.

- 중심 사건과 세계관 표현
- 세트 이름과 설명
- 물건 이름과 설명
- 이미 결정된 단서를 자연어 문장으로 표현
- 공개 상세 정보
- 소유자 전용 설명

알고리즘과 게임 도메인 로직은 다음을 담당한다.

- 실제 가치
- 세트 구성
- 세트 보너스
- 경매 순서
- 봇의 판단과 행동
- 낙찰 처리
- 점수 계산
- 동률 판정
- 시드 재현성
- 생성 결과 검증

생성 모델이 작성한 문장이 직접 점수, 실제 가치, 세트 정답을 결정해서는 안 된다.

### 2.3 플레이 중 생성 모델을 호출하지 않는다

한 게임에 필요한 표현 콘텐츠는 게임 시작 전에 준비한다. 플레이 중에는 저장된 데이터와 결정론적 알고리즘만 사용한다.

### 2.4 정보는 단계적으로 공개한다

- 게임 시작: 중심 사건과 세트 이름·분위기
- 카탈로그: 전체 물건의 기본 설명과 경매 순서
- 각 경매 직전: 해당 물건의 추가 공개 정보
- 낙찰 후: 공개 경매 결과
- 플레이어 낙찰 물건: 소유자 전용 추가 설명
- 최종 결과: 실제 가치, 실제 세트, 점수와 순위

## 4. 판타지 세계관과 게임 콘텐츠

### 4.1 세계관 방향

MVP는 현실 역사 인물이나 실제 문화재를 직접 사용하는 대신 가상의 판타지 세계관을 사용한다.

- 가상의 왕국, 항구, 귀족가, 학회, 종교, 전쟁, 의식, 사건
- 현실의 시대감·재료·골동품 분위기는 참고 가능
- 한 게임 안에서 서로 다른 장르와 시대를 무작위로 섞지 않음
- 고유명사는 자연스러운 한국어 표기를 기본으로 함
- 원어 병기는 기본적으로 사용하지 않음

### 4.2 중심 사건

각 게임은 하나의 중심 사건 또는 시대를 가진다.

예:

> **잿빛 왕위 계승전**  
> 북부 왕가의 단절 이후 세 가문이 왕위를 두고 충돌했던 시대다. 전쟁이 끝난 뒤 관련 유물들이 여러 지역과 기관으로 흩어졌다.

중심 사건은 12개 물건, 세트 3개, 반복 단서, 경매장 배경을 연결하는 공통 맥락이다.

### 4.3 세트 소개

게임 시작 시 세트 3개의 다음 정보만 공개한다.

- 세트 이름
- 한 줄 요약
- 짧은 세계관 설명
- `3개 구성`

공개하지 않는 정보:

- 실제 구성품
- 현재 보유 수량
- 진행도
- 완성 여부
- 세트 보너스
- 관련 물건 추천

세트 소개 화면은 세트 3개의 요약 카드를 한 화면에 보여주고, 각 카드를 열면 상세 설명 한 문단을 볼 수 있는 혼합형으로 구성한다.

### 4.4 세계관 정보 화면

중심 사건과 세트 소개는 게임 시작 시 최초로 표시한다. 이후 다음 위치에서 `세계관 정보` 화면을 다시 열 수 있다.

- 카탈로그
- 경매 화면
- 경매 결과 화면

경매 중 세계관 정보를 열면 타이머와 봇 진행을 일시정지한다.

## 5. 전체 게임 흐름

1. 메인 화면
2. 새 게임 설정
3. 게임 데이터 생성 또는 검증된 예비 프리셋 로드
4. 중심 사건 소개
5. 세트 3개 소개
6. 전체 카탈로그 공개 및 계획
7. 물건 1의 경매 준비 화면
8. 경매 진행
9. 경매 결과 확인
10. 사용자가 `NEXT →`를 눌러 다음 경매 진행
11. 최초 12개 경매 중 유찰 물건이 있으면 마지막 정상 경매 직전에 재경매 삽입
12. 모든 경매 완료
13. `RESULT →`
14. 최종 결과
15. 완료 기록 저장

### 5.1 최초 경매와 재경매 순서

- 최초 경매는 물건 1–12 순서로 진행한다.
- 최초 경매에서 유찰된 물건은 유찰 순서대로 재경매한다.
- 재경매는 **최종 정상 경매 바로 전**에 삽입한다.
- 최초 경매의 마지막 물건이 유찰되면 해당 물건은 재경매하지 않고 최종 유찰로 처리한다.
- 재경매에서도 실제 입찰이 없으면 최종 유찰로 처리한다.

진행 표시에서는 `물건 N / 12`와 추가 재경매 횟수를 구분해 보여준다.

## 6. 메인 화면과 새 게임

### 6.1 메인 화면 기능

- `새 게임 시작`
- 선택적 시드 입력
- 짧은 규칙 요약
- `히스토리`
- `도움말`

MVP에서 난이도, 봇 선택, 시작 자금, 물건 수, 세트 보너스 사용자 설정은 제공하지 않는다.

### 6.2 튜토리얼

- 3–4장의 짧은 카드
- 건너뛰기 가능
- 기본적으로 새 게임에서 표시
- `다시 보지 않기` 선택은 로컬에 저장
- 도움말에서 다시 볼 수 있음

### 6.3 시드와 버전

MVP 테스트를 위해 시드를 보이거나 입력·복사·재사용할 수 있다.

재현 키:

- 게임 시드
- 규칙 버전
- 알고리즘 버전
- 콘텐츠 버전
- 빌드 버전

같은 재현 키는 다음을 동일하게 만들어야 한다.

- 중심 사건
- 세트와 구성품
- 물건
- 실제 가치
- 경매 순서
- 봇 성향
- 알고리즘 랜덤 결과

표현 지연처럼 결과에 영향을 주지 않는 연출용 랜덤은 별도 RNG 스트림을 사용한다.

## 7. 카탈로그와 계획 화면

### 7.1 목적

플레이어가 경매 시작 전에 12개 물건 전체를 비교하고 자금 사용 계획과 세트 가설을 세울 수 있게 한다.

### 7.2 정렬

- 물건은 항상 경매 순서 1–12로 배치한다.
- 사용자 정렬과 검색은 제공하지 않는다.
- 필터를 사용해도 카드의 원래 순서는 변하지 않는다.

### 7.3 카드 기본 정보

- 대표 이미지
- 물건 이름
- 경매 순서
- 상태
- 기본 설명
- 관심 표시
- 플레이어 메모
- 경매 종료 후 최종 소유자
- 경매 종료 후 최종 가격

### 7.4 카드 확장 정보

- 공개 상세 정보
- 해당 물건의 경매 기록
- 유찰·재경매 기록
- 플레이어 소유 물건의 소유자 전용 설명

카탈로그를 나가면 카드 펼침 상태와 필터 상태는 초기화한다. 메모와 관심 표시는 유지한다.

### 7.5 필터

필터는 빠른 조건은 칩, 항목 수가 늘어나는 조건은 선택 메뉴를 사용하는 혼합형으로 디자인한다.

지원 조건:

- 전체
- 관심만 보기
- 소유자: 플레이어, 각 경쟁자, 소유자 없음
- 상태: 경매 예정, 경매 완료

조건은 조합할 수 있다. 세부 다중 선택 방식은 MVP 디자인 구현에서 결정한다.

활성 필터가 하나라도 있으면 오른쪽에 텍스트 버튼 `필터 초기화`를 표시한다.

빈 결과 문구:

- 관심 필터 단독: `관심 표시된 물건이 없습니다.`
- 다른 필터 또는 조합: `조건에 맞는 물건이 없습니다.`

### 7.6 관심 표시

- 미선택: `☆`
- 선택: `★`
- 선택 색상: 금색 계열
- 선택 카드에는 약한 금색 테두리
- 토글 시 짧은 강조 애니메이션
- 모션 감소 설정 존중
- 키보드 접근성 이름: `관심 표시 추가`, `관심 표시 해제`
- 경매 종료 후에도 읽기 전용 상태로 표시

### 7.7 플레이어 메모

각 물건에 플레이어 전용 자유 메모를 제공한다.

제공하지 않는 기능:

- 전역 메모
- 숫자 가치 추정 전용 필드
- 자동 세트 태그
- 자동 예산 계산
- 메모 정답 평가

메모는 해당 물건의 경매가 완전히 종료되면 읽기 전용으로 잠긴다. 재경매 예정 물건은 재경매 시작 전까지 수정할 수 있다.

---

## 8. 경매 준비 화면

각 경매 전에 자동으로 준비 화면을 연다.

### 8.1 최초 경매 준비 화면

표시 내용:

- `물건 N`
- 대표 이미지
- 기본 설명
- `새로 확인된 내용`
- 관심 표시
- 플레이어 메모
- 참가자 잔액
- `경매 시작`

`새로 확인된 내용`은 별도 분류 라벨 없이 짧은 사실 문장 목록으로 표시할 수 있다.

`경매 시작`을 누르기 전에는 타이머와 봇 행동이 시작되지 않는다.

### 8.2 재경매 준비 화면

표시 내용:

- `물건 N · 재경매`
- 시작 표시가 0
- 첫 입찰 최소 1
- 기본 설명
- 기존 공개 상세 정보
- 플레이어 메모
- 관심 표시
- 이전 유찰 기록

이전 유찰 기록은 기본 접힘 상태이며 `입찰 없음`을 표시한다. 펼치면 당시 참가자 잔액만 보여준다.

`경매 시작`은 화면 오른쪽 아래에 둔다. 버튼을 누르면 메모와 관심 표시를 잠그고 15초 타이머를 시작한다.

## 9. 공개 호가식 경매 규칙

### 9.1 기본 구조

- 모든 참가자는 경매 시작 시 참여 가능 상태다.
- 현재 최고가를 기준으로 차례대로 행동한다.
- 현재 최고 입찰자의 차례는 건너뛴다.
- 패스하거나 시간 초과된 참가자는 해당 물건 경매에서 다시 참여할 수 없다.
- 한 명만 남아도 실제 입찰을 해야 낙찰된다.

### 9.2 시작 가격과 첫 입찰

#### 최초 경매

- 공통 표시 시작가: 10
- 경매 시작 직후 최고 입찰자는 없음
- 첫 실제 입찰은 10 이상의 정수

#### 재경매

- 표시 시작가: 0
- 첫 실제 입찰은 1 이상의 정수

첫 실제 입찰 이후 최소 합법 입찰가는 `현재가 + 2`다.

### 9.3 플레이어 행동

플레이어는 다음 중 하나를 선택한다.

- 직접 금액 입력 후 입찰
- `+2`
- `+5`
- `+10`
- 패스

퀵 버튼은 현재 표시 가격을 기준으로 즉시 입찰한다. 각 버튼 위에 실제 적용될 금액을 표시한다.

직접 입력은 `Enter` 또는 `입찰` 버튼으로 즉시 실행하며 확인창과 되돌리기를 제공하지 않는다.

### 9.4 입력 필드

- 플레이어의 새 차례가 시작되면 최소 합법 입찰가를 기본값으로 입력
- 자동 포커스
- 전체 선택
- 숫자만 입력
- 소수점, 음수, 공백 금지
- 선행 0 제거
- 마우스 휠 및 방향키 증감 비활성화
- 포커스 중에는 구분 기호 없는 숫자
- 포커스를 잃으면 세 자리 구분 쉼표
- 입력 상한은 현재 잔액

읽기 전용 공간이 좁을 경우 향후 K/M/B 축약을 사용할 수 있다. 최대 소수 둘째 자리, 불필요한 0 제거, 표준 반올림을 임시 기준으로 한다.

### 9.5 잔액과 예상 잔액

- 통화 기호나 단위를 붙이지 않는다.
- 표기명은 `잔액`을 사용한다.
- 최고 입찰 중인 금액은 경매 종료 전까지 선차감하거나 예약하지 않는다.
- 플레이어가 아직 경매에 참여 가능한 동안 `낙찰 시 예상 잔액`을 표시한다.
- 예상 잔액은 현재 입찰 입력값 또는 현재 최고 입찰 상태를 기준으로 계산한다.
- 패스, 시간 초과, 입찰 불가 이후에는 숨긴다.

### 9.6 입찰 불가

다음 최소 합법 입찰가가 현재 잔액보다 크면 플레이어를 즉시 `입찰 불가` 상태로 전환한다.

- 패스를 기다리지 않는다.
- 예상 잔액을 숨긴다.
- 입찰 컨트롤을 비활성화한다.

봇은 플레이어에게 세부 사유를 공개하지 않고 모든 종료 사유를 `경매 이탈`로 통일한다. 내부 로그에는 원인을 구분한다.

### 9.7 시간 제한

- 플레이어의 행동 제한 시간: 15초
- 시간 초과: 즉시 자동 패스
- 추가 유예 시간 없음
- 플레이어가 현재 최고 입찰자이면 타이머 없음
- 카탈로그, 상세 정보, 보유 목록, 메모, 도움말, 세계관 정보를 열면 일시정지
- 닫으면 남은 시간부터 재개

### 9.8 한 명만 남은 경우

참여 가능한 참가자가 한 명뿐이어도 자동 낙찰하지 않는다.

- 실제 입찰 시 해당 금액으로 즉시 낙찰
- 패스 또는 시간 초과 시 유찰
- 아무도 첫 입찰을 할 수 없으면 유찰

### 9.9 첫 행동자

경매 시작 전 봇은 해당 물건에 대한 관심과 최대 지불 의사를 계산한다.

1. 10 이상 입찰할 의사가 있고 자금이 있는 봇 중 관심도가 가장 높은 봇이 첫 행동
2. 동률이면 시드 기반 RNG
3. 해당 봇이 없으면 플레이어가 첫 행동

이 특수 상황에서 플레이어가 먼저 입찰했다고 해서 봇이 경매 도중 새롭게 관심을 바꾸지는 않는다.

## 10. 봇 시스템

### 10.1 봇 성향

다섯 가지 프리셋 중 서로 다른 세 가지를 시드 기반으로 선택한다.

1. 세트 추적형
2. 개별 가치형
3. 자본 관리형
4. 비공개 정보 신뢰형
5. 공개 정보 중심형

봇 성향은 플레이어에게 공개하지 않는다. 이름과 아바타도 성향과 직접 연결하지 않는다.

### 10.2 봇이 사용할 수 있는 정보

- 초기 카탈로그 정보
- 해당 물건의 공개 상세 정보
- 자신의 소유자 전용 설명
- 자신과 다른 참가자의 공개 잔액
- 공개된 보유 물건
- 이전 경매 결과
- 자신의 성향 파라미터

봇은 실제 가치와 실제 세트 정답을 직접 볼 수 없다.

### 10.3 판단 시점

- 경매 시작 전에 최대 지불 의사 금액을 계산한다.
- 한 경매 안에서는 해당 값을 고정한다.
- 재경매 시 현재 상황을 반영해 다시 계산한다.
- 이전 공개 시장 결과는 미래 물건의 평가에 약하게 반영할 수 있다.
- 플레이어 행동을 학습해 성향 자체를 바꾸는 반응형 AI는 MVP에서 제외한다.

정확한 계산식, 가중치, 가격 평가 방식은 후속 재설계 영역이다.

### 10.4 행동 연출

플레이어가 아직 참여 중이면 봇 행동 사이에 0.5–1.5초의 연출 지연을 둔다.

- 결과용 RNG와 분리된 연출 전용 RNG 사용
- 경매 결과에는 영향 없음
- 플레이어가 경매에서 이탈하면 남은 연출 지연을 생략하고 결과로 이동
- 내부 입찰 이력은 정상적으로 계산·저장

`남은 경매를 계산 중` 같은 별도 메시지는 표시하지 않는다.

---

## 11. 유찰과 재경매

### 11.1 유찰 정의

실제 입찰이 한 번도 없을 때만 `유찰`이다.

### 11.2 재경매

- 최초 경매에서 유찰된 물건은 한 번 재경매
- 최초 유찰 순서 유지
- 최종 정상 경매 직전에 삽입
- 새로운 공개 단서나 콘텐츠는 추가하지 않음
- 재경매 시작가 0, 첫 입찰 최소 1

### 11.3 최종 유찰

다음 경우 최종 유찰이다.

- 재경매에서도 실제 입찰 없음
- 최초 경매의 마지막 정상 물건이 유찰됨

최종 유찰 물건:

- 소유자 없음
- 점수에 포함되지 않음
- 참가자 자금 변화 없음
- 게임 종료 시 실제 가치와 세트 소속 공개
- 비공개 소유자 설명 없음

---

## 12. 경매 종료와 라운드 결과

각 경매가 끝나면 자동으로 다음 경매로 넘어가지 않는다.

표시 내용:

- 낙찰자 또는 유찰
- 최종 가격
- 각 참가자의 최고 실제 입찰가 또는 `입찰 없음`
- 각 참가자의 경매 후 잔액
- 카탈로그와 보유 목록 접근
- 메모와 이전 기록 확인
- 플레이어 낙찰 시 소유자 전용 설명

소유자 전용 설명은 기본 접힘 상태이며 선택적으로 확인한다. 읽지 않은 설명에는 숫자 없는 빨간 점과 텍스트 또는 아이콘을 함께 사용한다. 열면 읽음 처리한다.

다음 진행 버튼:

- 일반: `NEXT →`
- 모든 경매 완료: `RESULT →`

버튼 문구와 아이콘은 추후 변경 가능하다.

## 13. 공개 정보와 비공개 정보

### 13.1 초기 카탈로그 정보

- 대표 이미지
- 물건 이름
- 경매 순서
- 분위기와 기본 사실이 결합된 설명
- 관심 표시
- 플레이어 메모

### 13.2 경매 직전 공개 상세

- 기본 설명
- 새로 확인된 짧은 사실 문장
- 상태·출처·제작 방식·문양·서명·손상 등

사실은 초기 정보와 충돌하면 안 된다. 확률이나 신뢰도 라벨은 표시하지 않는다.

### 13.3 소유자 전용 설명

모든 낙찰 물건에는 사전에 생성된 소유자 전용 설명이 있다.

- 1–3개의 짧은 사실 문장
- 실제 가치 숫자 또는 세트 정답 직접 노출 금지
- 향후 등장 물건과 연결되는 단서 가능
- 해당 소유자만 열람 가능
- 봇도 자신의 설명을 읽고 미래 판단에 사용할 수 있음

경쟁자의 소유자 전용 설명은 게임 종료 후에도 공개하지 않는다.

### 13.4 키워드 강조

인물·사건·장소·상징 등 연결 가능 키워드는 하나의 동일한 강조 스타일을 사용한다.

MVP에서는 다음을 제공하지 않는다.

- 범주별 강조색
- 키워드 클릭 링크
- 관련 물건 자동 추천
- 자동 관계 그래프

## 14. 점수와 순위

### 14.1 점수

최종 점수:

`보유 물건 실제 가치 합 + 히든 세트 보너스`

남은 자금은 점수에 포함하지 않는다.

### 14.2 세트 보너스

세트당 3개 구성품을 기준으로 한다.

- 2개 보유: +10
- 3개 보유: +35
- 2개 보너스와 3개 보너스는 누적하지 않음

예:

- 2개 보유 → +10
- 3개 보유 → +35

세트 보너스 수치는 MVP 임시값이다.

### 14.3 동률 판정

동점 시 다음 순서로 비교한다.

1. 완성한 세트 수
2. 부분 세트 수
3. 총 과입찰액이 낮은 참가자
4. 그래도 같으면 공동 순위

총 과입찰액은 각 낙찰 물건에 대해 `max(0, 낙찰가 - 실제 가치)`의 합으로 정의한다.

공동 순위가 발생하면 화면 표시 순서는 플레이어를 먼저 두고, 봇은 고정된 표시 순서를 따른다. 어떤 동률 기준에서 순위가 갈렸는지는 결과 화면에 공개하지 않는다.

---

## 15. 최종 결과 화면

결과 화면은 다음 네 영역으로 구성한다.

1. 전체 순위
2. 참가자별 결과
3. 세트 결과
4. 물건별 분석

구체적인 탭 또는 좌측 메뉴 배치는 MVP 디자인 구현에서 결정한다.

### 15.1 전체 순위

- `최종 1위`와 같은 중립적 표현
- 승리·패배 연출 없음
- 최종 점수
- 실제 물건 가치 합
- 세트 보너스
- 보유 물건 수
- 총 지출
- 최종 잔액

### 15.2 참가자별 결과

각 참가자에 대해 다음을 보여준다.

- 최종 순위
- 실제 물건 가치 합
- 세트 보너스
- 최종 점수
- 보유 물건 수
- 총 지출
- 최종 잔액
- 완성·부분 세트

봇의 내부 판단값과 비공개 설명은 공개하지 않는다.

### 15.3 세트 결과

각 세트에 대해 다음을 공개한다.

- 세트 이름
- 실제 구성품
- 최종 소유자
- 완성 또는 부분 보유 참가자
- 적용 보너스
- 세트 설명

구성품 목록은 접을 수 있으며 물건을 선택하면 물건별 분석으로 이동한다.

### 15.4 물건별 분석

- 물건 이름
- 낙찰자 또는 최종 유찰
- 낙찰가
- 실제 가치
- 실제 세트 또는 독립 물건
- 최초 경매 기록
- 재경매 기록
- 플레이어 메모
- 플레이어가 소유한 경우 소유자 전용 설명

게임은 플레이어의 메모나 추론이 맞았는지 자동 평가하지 않는다. 단서와 정답을 자동으로 문장 단위 연결해 해설하지 않는다.

### 15.5 결과 화면 동작

- 시드 복사
- 같은 시드로 다시 시작
- 새 자동 시드 게임
- 메인 화면
- 총 경과 시간
- 실제 플레이 시간

완료된 결과 화면에서 나갈 때 확인창은 표시하지 않는다.

---

## 16. 플레이 시간 측정

### 16.1 목표

- 권장 목표: 약 15분
- 임시 상한: 약 30분

### 16.2 지표

#### 총 경과 시간

새 게임 시작부터 결과 화면 최초 렌더까지의 시간. 일시정지 화면과 읽기 시간 포함.

#### 실제 플레이 시간

다음 시간을 제외한다.

- 카탈로그 탐색
- 상세 정보
- 도움말
- 세계관 정보
- 보유 목록
- 메모 작성
- 라운드 결과 검토
- 기타 명시적 일시정지 상태

결과 화면에는 두 값을 모두 표시한다. 히스토리 접힘 카드에는 총 경과 시간만, 펼침 상세에는 두 값을 모두 표시한다.

---

## 17. 히스토리와 로컬 저장

### 17.1 진행 중 게임

- 진행 중 저장·복구 없음
- 새로고침 또는 탭 종료 시 현재 게임 종료
- 플레이 중 `나가기` 또는 `새 게임`은 한 번 확인
- 가능한 경우 브라우저 이탈 경고 사용
- 결과 화면에서는 경고 없음

### 17.2 완료 기록

- 브라우저 로컬에 저장
- 최대 5개
- 최신순
- 6번째 저장 시 가장 오래된 기록 삭제
- 결과 화면이 처음 정상 렌더될 때 저장
- 완료 ID로 중복 저장 방지
- 같은 시드의 여러 완료 기록은 별도 기록

### 17.3 메인 화면 히스토리

메인 화면의 `히스토리` 팝업에서만 접근한다. 게임 중 또는 결과 화면에서 직접 히스토리 목록을 열지 않는다.

빈 상태:

`아직 완료한 게임 기록이 없습니다.`

### 17.4 접힌 기록

- 경매장 썸네일
- 경매장 이름
- 완료 날짜와 시간
- 순위
- 점수
- 세트 요약
- 총 경과 시간

### 17.5 펼친 기록

- 경매장 유형·이름·배경
- 점수 구성
- 세트 정보
- 보유 물건 수
- 총 지출
- 최종 잔액
- 플레이어 보유 물건 상세
- 경쟁자 요약
- 총 경과 시간
- 실제 플레이 시간
- 시드
- 시드 입력 방식: 자동 또는 직접 입력
- 규칙·알고리즘·콘텐츠·빌드 버전
- 같은 시드 다시 플레이

버전이 현재와 다르면 재현 결과가 달라질 수 있다는 경고를 표시한다.

### 17.6 저장하지 않는 정보

- 전체 긴 설명 원문
- 경쟁자 소유자 전용 설명
- 플레이어 메모
- 전체 시간순 입찰 로그
- 경쟁자 전체 보유 물건 상세
- 물건 이미지 원본

### 17.7 완료 시간

내부에는 절대 타임스탬프와 완료 시점의 시간대 정보를 저장한다. 화면에는 완료 당시 기기 로컬 시간으로 표시하며, 이후 기기 시간대가 바뀌어도 완료 당시 표기를 유지한다.

## 18. 생성 콘텐츠 API와 데이터 변환

### 18.1 설계 목표

생성 API의 응답 스키마와 실제 게임 도메인 데이터 스키마를 분리한다. 생성 모델, 프롬프트, 응답 형식이 바뀌어도 변환 계층에서 대응할 수 있어야 한다.

### 18.2 처리 흐름

1. 알고리즘이 기계적 판 구조를 생성한다.
2. 생성 API에 표현용 입력을 전달한다.
3. 생성 API가 구조화된 콘텐츠를 반환한다.
4. 응답 스키마를 검증한다.
5. 변환 계층이 게임 도메인 데이터로 재구성한다.
6. 기계적 사실과 표현 내용의 일치 여부를 검증한다.
7. 승인된 게임 팩을 저장한다.
8. 플레이 중에는 저장된 팩만 사용한다.

### 18.3 데이터 계층

#### 기계적 데이터

- 실제 가치
- 세트 ID와 구성품
- 세트 보너스
- 경매 순서
- 공개 단계
- 필수 단서 키
- 봇용 사실 태그
- 시드와 버전

#### 생성 응답 데이터

- 중심 사건 이름과 설명
- 세트 이름, 요약, 상세 설명
- 물건 이름과 기본 설명
- 공개 상세 문장
- 소유자 전용 설명
- 이미지 프롬프트 또는 이미지 참조 키
- 강조 가능한 키워드 후보

#### 게임 도메인 데이터

- 실제 UI에서 사용하는 정규화된 필드
- 기계적 사실과 표현 콘텐츠의 연결
- 공개 단계별 표시 데이터
- 로컬 저장용 최소 데이터
- 경매 상태와 결과 데이터

### 18.4 예시 타입

```ts
type GamePack = {
  identity: {
    gameId: string;
    seed: string;
    rulesVersion: string;
    algorithmVersion: string;
    contentVersion: string;
    buildVersion: string;
  };
  world: WorldPresentation;
  sets: HiddenSet[];
  items: AuctionItem[];
  participants: ParticipantDefinition[];
};

type WorldPresentation = {
  eventName: string;
  eventSummary: string;
  auctionHouseName: string;
  auctionHouseType: string;
  auctionHouseSummary: string;
  auctionHouseImageKey: string;
};

type HiddenSet = {
  id: string;
  name: string;
  shortSummary: string;
  detailedSummary: string;
  memberItemIds: [string, string, string];
  twoItemBonus: number;
  threeItemBonus: number;
};

type AuctionItem = {
  mechanics: {
    id: string;
    auctionOrder: number;
    actualValue: number;
    hiddenSetId?: string;
  };
  presentation: {
    name: string;
    catalogDescription: string;
    publicDetailStatements: string[];
    ownerOnlyStatements: string[];
    imageKey: string;
    highlightTerms: string[];
  };
};

type AuctionState = {
  phase:
    | "INTRO"
    | "CATALOG"
    | "PRE_AUCTION"
    | "BIDDING"

};
```

타입은 구현 언어와 실제 서버 구조에 맞게 변경한다.

## 19. 생성 검증과 예비 프리셋

### 19.1 검증 항목

#### 구조

- 물건 12개
- 경매 순서 중복 없음
- 세트 3개
- 세트당 실제 구성품 3개
- 총 세트 물건 9개
- 독립 물건 3개
- 실제 가치 범위 준수
- 필수 필드 존재
- 참조 ID 유효

#### 사실 일치

- 공개 문장이 기계적 사실과 충돌하지 않음
- 소유자 전용 문장이 실제 가치 숫자를 노출하지 않음
- 세트 정답을 직접 노출하지 않음
- 각 세트에 추론 가능한 반복 단서 존재
- 독립 물건이 부당하게 세트 정답처럼 보이지 않음
- 중심 사건과 모든 물건이 같은 세계관 맥락에 있음

#### 밸런스

- 고가 물건이 특정 구간에 과도하게 몰리지 않음
- 하나의 세트가 지나치게 우월하지 않음
- 단품 중심 전략도 완전히 무효하지 않음
- 봇이 초반에 항상 자금을 전부 소진하지 않음
- 최소 두 종류 이상의 합리적 자본 전략 존재

### 19.2 예비 프리셋

생성 또는 검증 실패 시 사전에 제작하고 검증한 예비 프리셋으로 게임을 시작할 수 있다.

예비 프리셋 사용은 정상적인 성공 흐름으로 보지 않는다.

- 내부 오류 로그 기록
- 실패 단계 기록
- 원인 및 재시도 횟수 기록
- 운영 지표 또는 개발 로그에 표시
- 반복 발생 시 버그 또는 장애로 판단

예비 프리셋은 사용자 플레이를 완전히 막지 않기 위한 복구 수단이다.

### 19.3 전체 실패

예비 프리셋도 로드할 수 없거나 필수 데이터가 손상된 경우 새 게임 생성 실패 상태를 표시하고 메인 화면으로 복귀할 수 있게 한다.

## 20. 경매장 배경

### 20.1 프리셋

시드가 다음과 같은 고정 유형 중 하나를 선택한다.

- 오래된 귀족 저택
- 비밀 항구 창고
- 박물관 수장고
- 희귀 서적 도서관
- 지하 시장

각 프리셋은 다음을 가진다.

- 경매장 이름 생성 규칙
- 대표 이미지
- 유형
- 1–2문장 배경

MVP에서는 게임마다 새로운 경매장 이미지를 생성하지 않고 준비된 프리셋 이미지를 사용한다.

### 20.2 경매장 정보

`세계관 정보` 화면에서 다음을 볼 수 있다.

- 중심 사건
- 경매장 이름·이미지·유형·배경
- 세트 3개의 이름
- 세트별 간단한 설명
- `3개 구성`

정확한 세트 구성품, 진행도, 추천, 보유 현황은 표시하지 않는다.

## 21. UI와 시각 디자인

### 21.1 방향

- 오래된 박물관
- 기록 보관소
- 희귀 서적 열람실
- 어두운 목재
- 황동
- 양피지
- 절제된 판타지 분위기

### 21.2 타이포그래피

- 서사·물건 이름·설명: 세리프 계열
- 버튼·숫자·상태·입력: 산세리프 계열

### 21.3 이미지

- 물건당 대표 분위기 이미지 1개
- 카탈로그, 상세, 결과에서 재사용
- 배경 이미지는 단서로 사용하지 않음
- 이미지가 기계적 사실과 충돌하면 안 됨

### 21.4 상태 표현

중요 상태는 색만으로 전달하지 않는다.

예:

- 색상
- 아이콘
- 텍스트

### 21.5 디자인 결정 원칙

칩·드롭다운·탭·간격·테두리·아이콘 등 세부 디자인은 다음 기준으로 MVP안을 정한다.

- 최소 해상도에서 핵심 기능 유지
- 오조작 방지
- 읽기 흐름
- 키보드 접근성
- 정보 밀도
- 플레이 중 중요한 숫자의 가독성

플레이테스트 이후 변경 가능하다.

## 22. 접근성

MVP에서 지원하는 기본 키보드 접근성:

- `Tab`, `Shift+Tab`으로 이동
- 버튼과 토글은 `Enter` 또는 `Space`
- 모달은 `Esc`로 닫기
- 명확한 포커스 표시
- 직접 입찰 입력에 포커스가 있을 때만 `Enter` 입찰
- 전역 단축키 없음
- 중요 상태는 색상 외 텍스트 또는 아이콘 병행
- 애니메이션은 모션 감소 설정 존중

키보드만으로 새 게임부터 최종 결과까지 핵심 진행이 가능해야 한다.

## 23. 오디오

MVP에는 다음을 포함하지 않는다.

- 배경 음악
- 효과음
- 음량 설정
- 음소거 설정

게임 상태와 결과는 시각 정보만으로 이해할 수 있어야 한다.

## 25. 오류와 이탈 처리

### 25.1 새 게임 생성 실패

- 재시도 가능한 경우 내부 재시도
- 예비 프리셋 사용 가능
- 예비 프리셋 사용 사실은 내부 버그 신호로 기록
- 전체 실패 시 사용자에게 간단한 오류와 재시도 또는 메인 이동 제공

### 25.2 플레이 중 종료

- 메인 이동 또는 새 게임 시작 시 확인
- 브라우저 종료·새로고침은 복구하지 않음
- 가능하면 브라우저 이탈 경고

### 25.3 경매 중 화면 이동

다음 화면을 열면 경매를 일시정지한다.

- 카탈로그
- 물건 상세
- 보유 목록
- 메모
- 도움말
- 세계관 정보

닫은 후 이전 경매 상태와 남은 타이머를 복원한다.

## 26. 내부 로그

UI에는 전체 시간순 입찰 로그를 노출하지 않지만 내부에는 보관한다.

권장 로그:

- 게임 생성 단계
- 생성 API 요청 ID
- 생성 검증 결과
- 예비 프리셋 사용
- 경매별 모든 행동
- 참가자별 내부 이탈 사유
- 봇 최대 지불 의사
- RNG 스트림과 결정 결과
- 점수 계산
- 동률 판정
- 완료 기록 저장 결과

운영 환경에서 민감하거나 불필요한 생성 원문을 장기간 보관하지 않도록 별도 정책을 둔다.

## 27. MVP 완료 기준

다음 조건을 모두 만족하면 MVP가 완성된 것으로 본다.

1. 새 게임에서 하나의 일관된 판타지 중심 사건이 표시된다.
2. 세트 3개의 이름·설명·`3개 구성`이 표시된다.
3. 12개 물건 전체가 경매 전에 공개된다.
4. 플레이어가 카탈로그, 메모, 관심 표시로 계획을 세울 수 있다.
5. 최초 경매 12개와 유찰 물건의 재경매 규칙이 정상 작동한다.
6. 공개 호가식 경매의 시작가, 최소 인상폭, 패스, 시간 초과, 입찰 불가가 정확히 작동한다.
7. 봇 3명이 규칙을 위반하지 않고 서로 다른 성향으로 행동한다.
8. 플레이어가 새 게임부터 최종 결과까지 정상 완주할 수 있다.
9. 실제 가치, 세트 보너스, 점수와 동률 판정이 정확하다.
10. 실제 가치와 실제 세트가 게임 종료 시 공개된다.
11. 결과 화면이 순위, 참가자, 세트, 물건 분석을 제공한다.
12. 완료 게임이 로컬 히스토리에 저장된다.
13. 동일 시드와 동일 버전으로 핵심 게임 데이터와 결과를 재현할 수 있다.
14. 자동화된 재현성 테스트가 통과한다.
15. 생성 실패 시 예비 프리셋으로 복구할 수 있고 내부 오류로 기록된다.
16. 최신 데스크톱 Chrome의 1366×768, 100% 확대에서 핵심 화면에 가로 스크롤이 없다.
17. 키보드만으로 핵심 게임 진행이 가능하다.
18. 치명적 오류 없이 여러 게임을 연속 완료할 수 있다.
19. 플레이테스트에서 플레이어가 최소 한 번 다음 판단을 경험한다.

> “이 물건에 더 쓰면 후반 목표를 놓칠 수 있다. 지금 경쟁할지 포기할지 결정해야 한다.”

## 28. 플레이테스트 질문

### 가치 판단

- 플레이어가 공개 단서로 물건 사이의 가치 차이를 추정할 수 있는가?
- 결과가 무작위처럼 느껴지지 않는가?
- 독립 물건과 세트 물건이 모두 전략적 선택지가 되는가?
- 소유자 전용 설명이 미래 판단에 의미 있는가?

### 세트 추론

- 시작 시 공개된 세트 설명이 방향은 주되 정답을 노출하지 않는가?
- 12개 카탈로그에서 후보 관계를 사전에 가정할 수 있는가?
- 단서가 지나치게 노골적이거나 모호하지 않은가?
- 세트 보너스가 단품 전략을 완전히 압도하지 않는가?

### 자본 운용

- 전체 카탈로그 공개가 실제 예산 계획으로 이어지는가?
- 플레이어가 후반 물건을 위해 초반 물건을 포기하는가?
- 공개 호가 과정에서 경쟁자의 잔액과 보유 물건을 고려하는가?
- 시작 자금 200과 가치 10–60이 적절한 압력을 만드는가?
- 15초가 판단에 충분하면서도 긴장을 유지하는가?

### 공개 호가

- 최소 인상폭 2가 지나치게 느리거나 빠르지 않은가?
- `+2/+5/+10`이 대부분의 상황을 충분히 지원하는가?
- 현재 최고 입찰자 차례 생략이 명확한가?
- 유찰과 재경매 규칙을 플레이어가 이해하는가?

### 결과

- 플레이어가 자신의 판단을 스스로 되짚을 수 있는가?
- 자동 해설 없이도 실제 가치와 세트 결과가 이해되는가?
- 점수 구성과 동률 결과가 납득되는가?
- 같은 시드 재도전 욕구가 생기는가?

### 생성 콘텐츠

- 판타지 세계관이 한 게임 안에서 일관적인가?
- 생성 문장이 기계적 사실을 정확히 전달하는가?
- 게임마다 이름만 바뀐 것이 아니라 전략적으로 다른 판이 되는가?
- 예비 프리셋과 생성 판의 품질 차이가 지나치게 크지 않은가?

## 30. 최종 방향 요약

미지의 경매장에서 생성 모델은 경매 결과를 결정하는 심판이 아니다. 이미 정의된 기계적 판을 하나의 일관된 판타지 세계와 물건으로 표현하는 콘텐츠 생성 계층이다.

알고리즘은 실제 가치, 세트, 봇 행동, 경매 결과, 점수, 재현성을 통제한다.

플레이어는 다음을 반복한다.

`전체 판 관찰 → 가치와 세트 가설 수립 → 자본 계획 → 공개 호가 참여 → 경쟁 또는 포기 → 수집 → 최종 정답 공개 → 판단 검증`

MVP의 중심은 단순히 좋은 물건을 사는 것이 아니라, **12개의 미래 기회 중 어디에 자본을 걸고 어디에서 물러날지 판단하는 경험**이다.
