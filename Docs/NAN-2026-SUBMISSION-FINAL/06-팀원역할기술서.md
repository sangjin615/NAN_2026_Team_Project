# 미지의 경매장 — 팀원 역할 기술서

> 기획·콘텐츠, 화면·비주얼, 엔진·검증을 나누고 공통 데이터 계약으로 결합한다

## 1. 협업 구조

팀은 기획·콘텐츠, 화면·비주얼, 엔진·검증을 나누고, 공통 데이터 계약을 통해 결과물을 결합한다. View Spec Lite 결과는 화면 골격과 좌표·크기·플로우를 제공하고, 게임 엔진은 경제 규칙과 상태를 관리하며, 생성 AI는 엔진이 허용한 표현 필드만 채운다.

## 2. 팀원별 역할

구분은 **기획 / 개발 / 아트 / AI 활용** 네 축이다. 대표 산출물은 저장소 커밋
기록으로 확인할 수 있는 것만 적었다.

| 팀원 | 구분 | 담당 영역 | 대표 산출물 (커밋 기록 기준) |
|---|---|---|---|
| 최재혁 | 개발 · AI 활용 · 툴 제작 | 게임 엔진, 상태 머신, 밸런스 로직, 테스트·시뮬레이션, 생성 API 연결과 검증, **제작 도구 두 종** | `Runtime/` 런타임 전체(`src` 218회, `test` 96회), 생성 라우터와 계약·검증기, 측정 도구와 기술 문서. **씬 플로우 편집 툴(VSL)** — 씬을 등급 체계로 계층 관리하고 연결선을 색·형태로 구분하며 편집 결과를 JSON으로 내보낸다. **밸런스 실험 엔진** — 이 게임의 밸런싱랩을 범용 툴로 개량해 시드별 시뮬레이션·Pareto 후보·결정 근거 자동 보관까지 처리한다 |
| 임상진 | 기획 · 아트 | 프로젝트 통합, 게임 기획·문서, 배경 및 화면 자료 정리, AI·런타임 연결 조율 | 경매품 이미지 정리(`Image/경매품`, `Image/2_경매품`), HTML 편집기 목업, 기획 브레인스토밍 문서, 밸런싱랩 그레이박스. 커밋 24건 |
| **[담당 확인]** (GitHub `GD_JM`) | 아트 | 경매품 60종 등급별 에셋 정리, V6.4 화면 에셋 | 경매품 6개 카테고리 등급별 스프라이트 정리, `Runtime/assets` 연결. 커밋 13건 |
| **[담당 확인]** | 기획 · 아트 | 화면 구조 검토, 비주얼 품질·스케일 조정, 핵심 UX 승인 | **[담당 확인]** — 커밋 기록 외 검토·승인 활동 |

> `git shortlog -sne --all`과 작성자별 변경 경로로 확인한 값이다.

## 3. 공동 작업 방식

1. 기획 문서와 밸런싱 자료에서 엔진 소유 수치와 AI 생성 문구를 분리한다.
2. View Spec Lite 결과의 씬·요소 ID를 매핑 계약에 연결한다.
3. 엔진 담당은 결정론적 규칙과 저장 상태를 구현하고, 콘텐츠/UI 담당은 화면과 표현을 연결한다.
4. AI 출력은 스키마, ID, 필수 필드, 금지 수치를 자동 검증한다.
5. 팀 검토자는 실제 플레이 화면과 기획 의도를 비교해 채택·수정 여부를 결정한다.

## 4. AI를 어떻게 나눠 썼나

이 팀에서 AI는 특정 담당자의 도구가 아니라 **모든 축에 걸쳐** 쓰였다. 축마다
사람이 맡은 몫이 다르다.

| 축 | AI가 한 것 | 사람이 한 것 |
|---|---|---|
| 아트 | 경매품 스프라이트 240개와 씬 배경 생성 | 무엇을 만들지 정하고, 나온 결과 중 쓸 것을 고르고, 등급별로 정리해 런타임에 연결 |
| 사운드 | 타이틀곡 생성 | 곡 방향 결정과 채택, 씬별 배치 |
| 개발 | 런타임 코드, 테스트, 측정 도구, 문서 작성 | 무엇이 필요한지 정하고, 결과를 받아들일지 판단하고, 어긋난 방향을 돌림 |
| 콘텐츠 | 플레이 중 LOT 문구·세트 사건 생성 | 생성 범위와 금지 규칙을 계약으로 설계하고, 검증기로 자동 확인 |

**개발 축의 분업이 특히 분명하다.** 사람이 코드를 한 줄씩 쓰지 않는 대신,
무엇을 만들지 정하고 나온 결과를 판단했다. 이 방식이 성립하려면 검증이
자동이어야 하므로 판단이 필요한 자리마다 기계가 읽을 수 있는 근거를 남기도록
만들었다 — 자세한 내용은 `02-AI활용기술.md` 4장에 있다.

## 5. 협업 원칙

AI 결과를 그대로 채택하지 않았다. 엔진 계약과 팀 검토를 통과한 결과만 실제 게임에 반영했다.

- **생성 문구**는 스키마·ID·금지 수치·문구 품질을 자동 검증한 뒤에만 화면에 오른다.
- **이미지와 음악**은 사람이 보고 채택한 것만 저장소에 들어간다.
- **코드**는 테스트 109건과 연결 점검(`npm run audit`)을 통과해야 커밋한다.
- **판단이 틀린 경우**도 문서에 남긴다. 표본이 모자라 단정하지 못한 수치, 되돌린
  결정, 자동 검증이 놓친 결함이 그대로 적혀 있다.
