# View Spec Lite가 프로젝트에 준 효과

## VSL의 역할

VSL은 게임 엔진을 대신하지 않는다. 사람이 만든 목업·좌표·크기·사운드·흐름을 **수정 가능한 중간 산출물**로 만들고, Codex가 그 구조를 읽어 런타임에 연결할 수 있게 하는 인터페이스다.

## 프로젝트에 직접 준 개선

1. 목업의 위치 정보를 JSON으로 넘길 수 있어 구현자가 화면을 다시 눈대중으로 재구성할 필요가 줄었다.
2. 상회·거래소·경매장 등 장소 이미지를 전체 배경으로 사용하고, 상호작용 UI만 별도 레이어로 올리는 구조가 가능해졌다.
3. 버튼·패널을 9-Slice로 늘릴 수 있어 원본 비율을 매 화면마다 다시 제작하지 않아도 된다.
4. 씬과 UI 상태가 분리돼 빈 화면이 남아 있어도 나중에 모듈을 끼워 넣을 수 있다.
5. export 결과를 런타임 어댑터와 계약에 연결할 수 있다.

## 실제로 발견하고 수정한 문제

VSL의 `normalizeLayoutElement` 과정에서 좌표 외 `actionRef`, `dataRefs` 같은 구현 메타데이터가 제거될 수 있었다. 이 상태로 계속 편집하면 화면은 보이지만 버튼 동작과 데이터 연결 정보가 사라진다.

대응:

- 편집기 정규화 시 원본 요소 필드를 보존하도록 수정
- 이미 export한 ZIP은 `Runtime/tools/repair-vsl-layout-export.py`로 복구
- 사용자가 수정한 `scene-continue` 좌표는 유지하면서 메타데이터를 재삽입
- 최신 편집기와 복구본을 하나의 LFS ZIP으로 배포

이 사례는 VSL의 효과를 “화면을 빨리 그렸다”로만 설명하지 않고, **사람이 수정해도 구현 정보가 보존되는 협업 파이프라인을 만들었다**는 근거다.

## 아직 주장하면 안 되는 것

- “UI 제작 시간이 몇 % 감소했다”: 전후 시간 측정 없음
- “모든 목업이 완성됐다”: 빈 상태와 세부 좌표 보정이 남을 수 있음
- “VSL만으로 게임 전체가 완성된다”: 실제 규칙·상태·데이터는 Runtime이 담당

## 제출 시 추천 화면

1. 목업 원본
2. VSL에서 같은 화면의 요소 선택·좌표·9-Slice 설정
3. export JSON
4. Runtime에서 실제 동작하는 동일 화면

이 네 장을 한 줄 흐름으로 보여주면 VSL이 프로젝트에 준 영향이 가장 명확하다.
