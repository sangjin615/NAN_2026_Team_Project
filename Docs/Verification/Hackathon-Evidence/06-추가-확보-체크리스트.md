# 제출 전 추가 증거 확보 체크리스트

현재 자료만으로도 기술 효과를 설명할 수 있다. 아래 항목을 채우면 “프로젝트 안에서 실제 효과가 있었는가”에 대한 설득력이 더 강해진다.

## 1. 사람이 30분 안에 할 일

- [ ] 최신 ZIP을 새 폴더에 풀고 VSL 실행기 화면 캡처
- [ ] `이어하기` 화면에서 요소 하나의 좌표를 바꾸기 전/후 캡처
- [ ] 같은 ZIP을 Runtime에 적용한 화면 캡처
- [ ] 도시→경매→감정→판매→결산을 1회 녹화
- [ ] `npm.cmd test`의 8/8 결과 캡처
- [ ] 900시드 보고서 JSON 또는 표 캡처

## 2. 시간 절감 측정

동일한 작은 화면 하나를 정한다. 예: 이어하기 슬롯 1개와 버튼 2개.

- A 방식: 이미지/CSS/코드로 수동 재현
- B 방식: VSL에서 배치 후 JSON 반영
- 시작·종료 시각, 수정 횟수, 최종 오차 요소 수 기록
- 공식: `(A분 - B분) / A분 × 100`

한 사람이 두 방식을 연속 수행하면 학습 효과가 섞인다. 가능하면 순서를 바꾼 2회 측정이나 서로 다른 팀원 2명이 수행한다.

## 3. AI 문장 품질 측정

동일한 10일 요청을 장문 프롬프트와 스킬/하네스로 각각 생성한다.

- 계약 첫 시도 통과율
- 최종 통과율
- 평균 재시도 횟수
- P50/P95 시간
- 사람이 고친 LOT 비율
- 문장 반복·세계관 위반·ID 변경 건수

현재 0/2 대 3/3은 방향성 증거로만 사용하고, 최소 10회씩 확보하면 본문 핵심 수치로 올릴 수 있다.

## 4. 플레이 효과 측정

최소 3명에게 같은 빌드를 1일차까지 플레이하게 한다.

- 경매 시작 도달 여부
- 감정→구매/포기→판매→결산 완료 여부
- 막힌 화면과 원인
- 5점 척도: 이해도, 흥미, 정보 신뢰, 다시 플레이 의향
- 자유 의견 한 문장

## 5. ChatGPT/Codex 과정 증거

- [ ] ChatGPT 대화 export 또는 공유 링크 확보
- [ ] Codex 작업 목록에서 주요 작업 제목·날짜 캡처
- [ ] 요구→오류 발견→수정→테스트 통과가 이어지는 대화 3개 선정
- [ ] 개인 정보·토큰·로컬 비밀키 제거
- [ ] 대화 원문을 성과 수치 대신 과정의 보조 증거로만 사용

## 6. 제출 금지 항목

- `.team-loop/actual-run-data/app-secret.key`
- `.env` 및 API 키
- 개인 계정 정보가 표시된 브라우저 캡처
- 검증되지 않은 “몇 배 향상”, “완전 자동화”, “100% 완성” 문장
