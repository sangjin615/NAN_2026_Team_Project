# 브레인스토밍 요청 — 001 핵심 재미

## 목적

`docs/00-product-spec.md`를 기준으로 미지의 경매장의 핵심 재미를 서로 다른 설계 방향으로 탐색하고, MVP가 보호해야 할 플레이어 판단을 선택할 근거를 만든다.

이 실행은 구현 작업이나 제품 명세 수정을 만들지 않는다.

## 기준 자료

- 기준 명세: `docs/00-product-spec.md`
- 기존 시안: `docs/brainstorms/001-core-fun.baseline.md`

기존 시안은 정답이나 우선 후보가 아니다. 모든 신규 후보가 작성되기 전에는 비교에 사용하지 않는다.

## 불변 조건

- 싱글플레이
- 물건 12개와 전체 카탈로그 사전 공개
- 플레이어 1명과 알고리즘 경쟁자 3명
- 제한된 자본
- 숨겨진 실제 가치와 세트 관계
- 생성 모델은 표현, 알고리즘은 판정
- 플레이 중 생성 모델 호출 없음
- 종료 후 판단 복기

## 탐색 질문

1. 플레이어가 가장 자주 내려야 할 의미 있는 결정은 무엇인가?
2. 전체 카탈로그가 실제 자금 계획으로 이어지려면 무엇이 필요한가?
3. 세트는 정답 퍼즐이 아니라 자본 투자 가설로 어떻게 작동해야 하는가?
4. 경쟁자는 어떤 방식으로 가격과 미래 기회비용을 만들어야 하는가?
5. 생성 콘텐츠가 이름 교체 이상의 전략 차이를 만들려면 무엇을 구조화해야 하는가?
6. 최종 결과가 플레이어 대신 채점하지 않으면서 판단을 복기하게 하려면 무엇을 보여줘야 하는가?
7. 한 판에서 반드시 한 번 일어나야 할 선택은 무엇인가?

## 후보 생성 계약

정확히 5개의 후보를 만든다. 표현만 다르고 핵심 루프가 같은 후보는 허용하지 않는다.

1. 가치 추론 중심안
2. 히든 세트 투자 중심안
3. 자본 운용 중심안
4. 공개 호가 경쟁 압력 중심안
5. 비공개 동시 입찰 계획 중심안

각 후보는 다른 후보의 결론을 참조하지 않고 독립적으로 작성한다. 후보마다 다음을 포함한다.

- 한 문장 정의
- 핵심 루프
- 반복되는 플레이어 판단
- 전체 카탈로그의 역할
- 경쟁자의 역할
- 정보 공개 구조
- 현재 명세에서 바뀌는 가설
- 장점
- 가장 강한 반론
- 예상 실패 양상
- 구현 복잡도
- 자동 검증 방법
- 최소 플레이테스트 방법과 성공·실패 기준

## 비교 기준

각 항목을 1–5점으로 평가하고 반드시 근거를 적는다. 총점만으로 추천안을 결정하지 않는다.

- 핵심 재미의 명확성
- 의미 있는 결정의 빈도
- 전체 카탈로그 활용도
- 생성 콘텐츠의 전략적 효용
- 공정성 및 납득 가능성
- 15–30분 플레이 적합성
- 구현 복잡도
- 자동 검증 가능성
- 플레이테스트 가능성
- 장기 확장성

## 비판 단계

- 각 후보에 가장 강한 반론을 하나 이상 제시한다.
- 후보 공통의 실패 가능성을 분리한다.
- 현재 제품 명세가 지나치게 일찍 확정한 가설을 지적한다.
- 기존 시안이 신규 후보보다 나은 조건과 나쁜 조건을 모두 적는다.
- 근거 없는 확신은 `추정`으로 표시한다.

## 종료 조건

- 추천안 하나와 차선안 하나를 구분한다.
- 추천안에 대한 가장 강한 반론을 보존한다.
- 선택을 바꿀 수 있는 조건을 명시한다.
- 열린 질문을 억지로 결정하지 않는다.
- 사람이 선택하기 전 제품 명세와 구현 파일을 수정하지 않는다.
