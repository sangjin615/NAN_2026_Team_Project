## 게임 프로젝트에 생긴 효과

### 이전

- 기획서와 밸런싱 시뮬레이션은 있었지만 최종 게임 화면과 규칙이 하나의 상태로 연결되지 않았다.
- 목업은 정적 이미지였고 장소 이동, 낙찰품, 현금, 의뢰, 대출이 같은 플레이 세션에서 이어지지 않았다.
- 생성 API와 VSL 결과물을 받을 명시적 입출력 계약이 없었다.

### 현재

- 12일 × 8 LOT, 총 96 LOT이 하나의 런으로 동작한다.
- 도시·의뢰소·경매장·거래소·상회·조합·유물 전시관이 같은 상태 데이터를 공유한다.
- 경매, 인벤토리, 감정, 판매, 시세, 세트, 의뢰, 상점, 대출, 마감, 파산, 유물이 연결된다.
- API가 없어도 현재일에서 2일 뒤까지 로컬 폴백 콘텐츠를 준비한다.
- 플레이 행동을 JSON으로 내려받아 완주·실패 원인을 측정할 수 있다.
- VSL과 생성 API가 도착하면 규칙 전체를 다시 만들지 않고 어댑터와 계약을 연결할 수 있다.

## 아직 수치화할 수 없는 부분

VSL ZIP과 실제 API가 아직 없으므로 다음 수치는 현재 단계에서 확정할 수 없다.

- 수동 UI 제작 대비 VSL 적용 시간 절감률
- 생성 API 성공률과 평균·95% 응답 시간
- 수동 수정 없이 배치된 VSL 요소 비율
- 실제 플레이테스터 완주율과 만족도

이 값은 결과물 수령 후 동일 화면·동일 시드 기준으로 측정한다. 현재 단계에서는 임의의 개선율을 만들지 않는다.

## 제출 관점의 현재 결론

현재 확인 가능한 가장 큰 효과는 단순한 툴 제작량이 아니라, 미지의 경매장 프로젝트가 **정적 문서와 목업에서 반복 실행·재현·측정 가능한 게임 프로토타입으로 이동했다는 점**이다. VSL과 API 도착 후에는 제작 시간과 콘텐츠 다양성까지 수치로 확장할 수 있다.

원본 자동 측정값은 `Runtime/reports/project-evidence-current.json`에 저장한다.

## 로컬 생성 선행 실험

실제 API 연결 전 Team Loop와 `qwen3:14b`로 2단계 생성을 실행했다. 런 골격은 28.274초에 계약을 통과했다. 최초 일일 생성은 23.797초 후 LOT ID 한 개를 변형해 실패했고, 식별자 고정과 자동 교정을 추가한 뒤 19.511초에 통과했다. 이 결과로 API 연결 전에도 스키마 실패·교정·폴백 정책을 실제 사례로 검증했다.
