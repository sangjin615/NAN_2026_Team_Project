# 미지의 경매장 VSL 모듈형 프로토타입

최종 VSL ZIP을 받기 전에 게임 규칙과 생성 결과 계약을 검증하기 위한 독립 실행 런타임이다. 화면은 `MockVslAdapter` 뒤에 분리되어 있어 VSL 산출물이 도착하면 어댑터와 좌표 매핑을 교체한다.

## 실행

```bash
npm start
```

`http://localhost:4173/`에서 실행한다. 검증은 `npm test`로 수행한다.

## 현재 연결된 시스템

- 12일 × 하루 8 LOT, 총 96 LOT 고정 생성
- 60종 아이템과 240개 등급별 스프라이트
- API 실패 시 로컬 대체를 포함한 현재일 + 2일 생성 버퍼
- `npm.cmd run start:generation --prefix Runtime`으로 Ollama 기반 `/generate` 중계 API 실행
- HTML은 동일 계약을 사용하므로 제출 시 엔드포인트와 서버 모델 어댑터만 외부 API로 교체
- 경쟁 봇 입찰, 플레이어 낙찰, 현금과 창고 한도
- 계열별 시세, 감정, 세트 배수 판매
- 하루 3개 의뢰 제시, 최대 2개 수주와 정산
- 4단계 상점 성장, 수수료와 창고 확장
- 담보 대출, 2일 만기 상환과 연체 압류
- 12일차 일반 경매 결산 후 13일차 도시로 복귀하고, 경매장 진입 시 3라운드 유물 경매 진행
- 로컬 저장 및 이어하기
- 도시 기반 장소 이동과 장소별 독립 화면
- 물품별·선택 감정/판매와 정보 구매
- 반복 호가와 경쟁자 응찰 기록
- JSON 플레이 기록 다운로드
- 생성 API 계약·클라이언트·제한 시간·재시도·폴백
- 사운드 매핑용 AudioBus와 빈 매니페스트

## VSL 도착 후 교체할 부분

- 최종 씬 요소 ID, 좌표, 크기, 전환 애니메이션
- 버튼·팝업·SFX·BGM의 실제 VSL 이벤트 매핑
- 생성 API 인증 및 응답 스키마 연결

게임 상태와 규칙 모듈은 화면 구현과 분리되어 있으므로 위 항목을 교체해도 일정·경매·경제·메타 진행 데이터는 그대로 사용한다.

## 밸런스 기준

규칙의 계산 방식은 `auction-round/밸런싱랩/greybox/rules-v6.js`를 행동 기준으로 삼는다. 실제 수치는 프로젝트의 `data/balance.json`을 우선하므로, 다운로드본과 충돌하는 감정 비용 9.5%와 담보 비율 35%는 프로젝트 값을 유지한다.
